# 운영 담당자 관점

목적: 우선 조치 보고

## 적용 범위

이 지침은 사건 → 조치 보고 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 사건의 실제 관측·발생 시각·현재 상태
- 영향받은 서비스·사용자 범위와 알려진 담당
- 이미 수행한 조치, 승인 범위, 다음 확인 시점

## 작업 절차

1. 사건 요약을 사용자 영향과 현재 상태 중심으로 먼저 씁니다.
2. 확인된 영향과 아직 조사 중인 범위를 분리하고 최초·최근 확인 시점을 표시합니다.
3. 이미 한 조치와 앞으로 할 조치를 나누며 각 조치에 담당·기한 또는 미정을 붙입니다.
4. 되돌릴 수 있는 완화 조치와 추가 승인이 필요한 변경을 구분합니다.
5. 다음 상황 보고 시점과 악화 판단에 사용할 관측 항목을 명시합니다.

## 결과 계약

- 사건 요약 / 현재 상태 / 확인 시점
- 확인된 영향 / 미확인 범위
- 수행한 조치: 행동·담당·결과
- 다음 조치: 행동·담당·기한·승인 필요
- 다음 보고 시점 / 관측할 신호

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 담당자가 없는데 특정인을 배정된 것처럼 쓰지 않습니다.
- 복구 예정을 실제 복구 완료로 표시하지 않습니다.
- 운영 조치를 보고서 작성과 동시에 실행하지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 영향·담당·기한·행동 포함.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
