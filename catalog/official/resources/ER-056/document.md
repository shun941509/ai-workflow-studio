# 관계·출처 온톨로지†

문서 ID: ER-056 / 버전 1.0 / 기준일 2026-10-01

이 문서와 데이터의 기관 “한빛 업무연구소”, 제품 “라온 협업보드”, 역할·업무·기록은 모두 가상입니다. 실제 고객·개인·제3자 문서를 사용하지 않았습니다. 예시를 실제 서비스 정책이나 사건으로 오인하지 마세요.

## ONTO-01 관계 계약
관계 레코드는 id·type·from·to·sourceId를 요구합니다. from→to 방향과 허용된 개체 유형을 검사합니다. 별칭 해소가 불명확한 상태에서 간선을 확정하지 않습니다.

- USES: service → dataset; 서비스가 데이터셋을 사용한다.
- BACKED_UP_BY: dataset → service; 데이터셋의 백업을 서비스가 담당한다.
- OWNED_BY: service → role; 서비스 운영 책임 역할.
- DEPENDS_ON: service → service; 서비스 운영 의존; 인과 보장 아님.

## ONTO-02 원문 근거
- SRC-1, 2.1: 라온 협업보드는 업무 카드 저장소를 사용한다.
- SRC-2, 3.2: Atlas API는 보고서 저장소를 사용한다.
- SRC-3, 4.1: 업무 카드 저장소는 보관 서비스의 백업 대상이다.
- SRC-4, 5.1: 라온 협업보드의 운영 책임 역할은 운영 역할이다.
- SRC-5, 5.2: Atlas API는 라온 협업보드에 의존한다.

## ONTO-03 올바른 간선
edges.json의 5개 간선은 위 원문과 entities.json을 연결합니다. E-3은 DATA-CARDS→SVC-BACKUP 방향입니다. “보관 서비스가 카드 저장소를 사용한다”라는 역방향 USES로 바꾸면 원문과 다른 관계가 됩니다.

## ONTO-04 거절할 후보
sourceId 없는 간선, 미등록 개체, ROLE-OPS→DATA-CARDS의 USES는 계약에 맞지 않습니다. DEPENDS_ON 경로가 있다는 사실만으로 특정 장애의 원인이나 실제 복구 성공을 주장하지 않습니다.
