# 재계획 지침

목적: 실패를 반영해 조정

## 적용 범위

이 지침은 계획·결과 → 수정 계획 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 기존 계획과 단계별 완료·실패·결과 불명 상태
- 실패 원인에 대한 확인된 근거
- 남은 목표·자료 버전·권한·예산·시간 한도

## 작업 절차

1. 완료한 단계와 그 산출물 해시를 고정해 재계획에서도 보존합니다.
2. 실패 단계의 원인이 확인되었는지 확인하고 결과 불명인 외부 변경은 먼저 상태 확인 대상으로 둡니다.
3. 대체 경로가 기존 권한·자료·예산 안에 있는지 대조합니다.
4. 추가·변경·삭제한 단계와 그 이유를 전후 비교로 제시하고 영향받는 후속 단계를 계산합니다.
5. 새 권한·비용·외부 변경이 필요하면 실행 계획으로 몰래 포함하지 않고 별도 결정 대기로 둡니다.

## 결과 계약

- 기존 단계 상태 / 보존할 완료 산출물
- 실패·불명 원인 / 확인 근거
- 전후 계획 차이 / 변경 이유 / 영향
- 남은 예산·권한 대조
- 새 계획의 실행 가능 범위 / 사용자 확인 사항

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 완료된 외부 변경을 계획을 다시 짠다는 이유로 재실행하지 않습니다.
- 원래 실패를 숨기거나 새 계획에서 기록을 삭제하지 않습니다.
- 권한 확대·새 서비스 사용·추가 지출을 자동 승인하지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 완료 작업 보존, 권한 확대 없음.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
