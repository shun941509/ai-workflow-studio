# 요청 구체화 지침

목적: 실행 조건 정리

## 적용 범위

이 지침은 요청 → 목표·질문 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 사용자의 원래 요청과 작업이 필요한 이유
- 원하는 산출물·독자·사용 시점
- 이미 정한 범위, 제공 자료, 수정하면 안 되는 조건

## 작업 절차

1. 원래 요청에서 목표, 산출물, 필수 제약을 분리하고 각 항목에 원문 표현을 붙입니다.
2. 누락 항목을 실행을 막는 정보와 나중에 조정할 정보로 나눕니다. 색상처럼 되돌릴 수 있는 세부 선호는 첫 질문에서 제외합니다.
3. 실행을 막는 누락만 한 번에 최대 세 가지로 질문합니다. 답을 선택할 수 있으면 의미가 겹치지 않는 선택지를 제공합니다.
4. 가정을 사용할 수 있는 항목은 가정임을 명시하고, 사용자의 실제 답과 섞지 않습니다.
5. 답을 받으면 목표와 완료 조건을 한 문장씩 다시 쓰고 작업 범위를 고정합니다. 답하지 않은 필수 조건은 미정으로 남깁니다.

## 결과 계약

- 목표: 무엇을 바꾸거나 알아낼 것인가
- 산출물: 형태·독자·제출 위치
- 확정 조건: 원문 근거와 함께 기록
- 필수 질문: 질문 / 필요한 이유 / 선택지
- 가정: 적용 범위 / 바뀌면 달라지는 작업
- 실행 가능 여부: 가능 또는 필수 답변 대기

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 담당자·기한·예산을 임의로 배정하지 않습니다.
- 이미 답한 내용을 반복해서 묻지 않습니다. 서로 충돌하는 답은 충돌 내용만 확인합니다.
- 외부 발송이나 비용 발생은 모호한 요청에서 허용된 것으로 추정하지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 필수 누락만 질문, 가정 표시.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
