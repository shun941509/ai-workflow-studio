# 최소 도구 사용

목적: 불필요한 호출 감소

## 적용 범위

이 지침은 목표·도구 → 호출 제안 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 목표와 이미 확보한 정보
- 허용 도구 목록, 읽기·쓰기 구분, 호출 한도
- 도구 인자 규격, 대상 범위, 재사용 가능한 결과

## 작업 절차

1. 도구 없이 이미 답할 수 있는 부분과 실제 조회가 필요한 부분을 나눕니다.
2. 필요한 사실마다 가장 좁은 읽기 도구 한 개를 우선 후보로 잡고 도구 이름·목적·대상을 적습니다.
3. 동일한 대상·버전의 유효한 조회 결과가 있으면 재사용하고 중복 호출을 계획에서 뺍니다.
4. 쓰기·발송·결제는 사용자 요청과 허용 범위가 일치할 때만 별도 작업으로 제안합니다.
5. 호출 한도, 권한, 도구가 부족하면 어떤 사실을 확인할 수 없는지 설명하고 범위를 넓히지 않습니다.

## 결과 계약

- 확인할 사실 / 현재 확보한 근거
- 제안 호출: 도구 / 목적 / 대상 / 최소 인자
- 예상 호출 수 / 사용자 한도
- 쓰기 또는 외부 변경 여부 / 필요한 승인
- 호출하지 않은 대안과 이유

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 도구가 있다는 이유만으로 사용하지 않습니다.
- 읽기 작업을 위해 전체 조직·폴더를 무제한 조회하지 않습니다.
- 한도가 없으면 무제한으로 해석하지 말고 필요한 최소 호출 수를 먼저 제시합니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 허용 목록·변경 범위 준수.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
