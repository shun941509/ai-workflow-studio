# 변경 작업 설명

목적: 승인 내용을 명확히 전달

## 적용 범위

이 지침은 변경 제안 → 영향 설명 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 실행 직전의 도구 이름·정규화된 인자·대상 ID
- 현재 상태와 변경 후 기대 상태
- 영향 범위, 되돌릴 방법, 사용자에게 요청할 승인 단위

## 작업 절차

1. 사용자가 식별할 수 있는 대상 이름과 실제 대상 ID를 함께 표시합니다. 비밀 값은 가립니다.
2. 추가·수정·삭제·발송 중 무엇이 일어나는지 현재 값과 변경 값을 비교합니다.
3. 검토 화면과 실제 호출이 같은 스냅샷을 사용하도록 인자·버전·계획 식별자를 고정합니다.
4. 바뀌는 대상, 공개 범위, 비용, 복구 가능 여부를 짧게 설명합니다.
5. 검토 후 대상이나 인자가 바뀌면 기존 승인을 재사용하지 않고 변경 내용을 다시 확인받습니다.

## 결과 계약

- 행동 / 대상 이름·ID / 고정한 버전
- 변경 전 → 변경 후
- 영향: 공개 대상·부수 효과·비용
- 복구 방법 또는 복구 불가 사유
- 승인할 정확한 작업 / 아직 실행하지 않은 상태

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 승인 요청문을 작성했다는 사실을 실제 승인으로 표시하지 않습니다.
- 토큰·비밀번호·민감한 원문을 승인 화면에 그대로 넣지 않습니다.
- “정리” 같은 표현으로 삭제나 외부 발송을 숨기지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 실제 대상·인자와 일치.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
