# 완료 조건 지침

목적: 판정 기준 작성

## 적용 범위

이 지침은 작업 → 완료 조건 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 검증할 작업·산출물과 사용자 요구사항
- 필수 항목, 허용 오차, 제출 환경
- 검사에 사용할 실제 파일·필드·관측 방법

## 작업 절차

1. “좋게”, “빠르게”, “완벽하게” 같은 표현을 그대로 합격 조건으로 쓰지 말고 관측 가능한 결과를 찾습니다.
2. 요구사항마다 검사 대상의 위치를 지정합니다. 문서 절, JSON 필드, 파일 이름처럼 검토자가 다시 찾을 수 있어야 합니다.
3. 검사 방법과 합격 기준을 분리해 적습니다. 수치 기준이 제공되지 않았으면 제안으로 표시하고 확정 여부를 남깁니다.
4. 결과가 없는 경우와 결과는 있으나 불합격인 경우를 구분합니다. 검사 불가를 통과로 바꾸지 않습니다.
5. 모든 필수 요구에 기준이 연결되었는지 역으로 대조하고, 증거가 없는 행은 미검증으로 둡니다.

## 결과 계약

- 요구 ID / 요구 내용
- 검사 대상: 파일·절·필드 또는 화면 위치
- 검사 방법: 재현 순서 또는 대조 규칙
- 합격 조건: 기대값·오차·예외
- 판정: 통과 / 실패 / 미검증
- 증거 위치 / 확인할 담당 또는 후속 작업

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 검사 코드를 만들었다는 이유만으로 실제 산출물이 통과했다고 쓰지 않습니다.
- 존재하지 않는 파일, 실행 로그 또는 점수를 증거로 만들지 않습니다.
- 필수 기준을 충족하지 못했는데 평균 점수로 상쇄하지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 대상·검사 방법 존재.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
