# 재시도 판단

목적: 실패와 결과 불명 구분

## 적용 범위

이 지침은 실패 → 확인·재시도 제안 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 작업 ID·시도 ID·도구 종류와 변경성 여부
- 마지막 응답·오류·확인된 외부 상태
- 멱등 키·중복 방지 기능·조회 방법·재시도 한도

## 작업 절차

1. 시도를 성공 확인, 변경 전 실패 확인, 결과 불명으로 분류합니다.
2. 시간 초과나 연결 단절만으로 외부 작업이 실패했다고 단정하지 않습니다.
3. 쓰기 작업의 결과가 불명이면 기존 작업 ID나 멱등 키로 상태를 조회하는 계획을 우선 제시합니다.
4. 변경 전 실패가 확인되었거나 동일 멱등 키의 중복 방지가 보장되는 경우에만 제한된 재시도 후보를 만듭니다.
5. 조회로도 결론이 안 나면 담당자의 외부 상태 확인을 요청하고 재전송 대기로 기록합니다.

## 결과 계약

- 작업·시도 ID / 마지막 확인 시점
- 상태 분류 / 근거
- 안전한 상태 조회 방법
- 재시도 허용 여부 / 동일 멱등 키 / 남은 한도
- 담당자가 확인할 외부 상태와 금지된 다음 행동

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 결과 불명인 결제·발송·생성 요청을 새 요청 ID로 자동 재전송하지 않습니다.
- 이미 발생한 변경을 취소 또는 롤백된 것으로 표시하지 않습니다.
- 읽기 실패에도 무한 재시도하지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 불명확한 변경의 재전송 금지.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
