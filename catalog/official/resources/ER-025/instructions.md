# 빌드 오류 분석

목적: 오류 원인 후보 축소

## 적용 범위

이 지침은 로그 → 최초 오류·조치 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 전체 빌드 명령과 첫 실패부터의 실제 로그
- 언어·도구·운영체제 버전 및 최근 변경 범위
- 재현 가능한 작업 디렉터리와 관련 설정 파일

## 작업 절차

1. 로그에서 최초의 원인 가능 오류와 그 뒤 연쇄 오류를 구분합니다.
2. 오류가 가리키는 파일·행·심벌을 실제 제공 파일과 대조하고 없는 경로는 미확인으로 둡니다.
3. 환경 불일치, 의존성 해석, 타입·문법, 생성 파일 누락 등 가능한 범주를 근거에 따라 좁힙니다.
4. 가설 하나를 확인할 최소 읽기 검사 또는 해당 오류를 겨냥한 변경을 제안합니다.
5. 변경 후에는 처음 실패한 명령을 다시 확인하는 계획을 적고 재실행 전에는 해결 완료라고 쓰지 않습니다.

## 결과 계약

- 실패 명령 / 환경 / 최초 오류 위치
- 직접 원인 후보 / 근거 로그
- 연쇄 오류로 보이는 항목
- 최소 확인 또는 수정 / 영향 범위
- 재실행할 검증 / 현재 확인 상태

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 근거 없이 잠금 파일 삭제·전체 의존성 업그레이드·전역 설정 변경을 제안하지 않습니다.
- 로그의 비밀·환경 값을 복사해 보고서에 노출하지 않습니다.
- 코드가 없으면 존재하지 않는 구현을 전제로 수정했다고 주장하지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 핵심 로그 근거, 무관한 변경 억제.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
