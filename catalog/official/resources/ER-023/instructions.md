# 성능 분석 지침

목적: 측정값 해석

## 적용 범위

이 지침은 측정값 → 가설·확인안 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 기준·현재 측정값과 단위·표본 수
- 하드웨어·버전·부하·측정 구간 등 조건
- 지표 정의와 목표 또는 허용 변동

## 작업 절차

1. 두 측정의 지표·단위·조건이 같은지 먼저 대조합니다. 조건이 다르면 직접 비교의 한계를 표시합니다.
2. 절대 변화와 상대 변화를 구분해 계산합니다. 기준값이 0이면 비율을 억지로 만들지 않습니다.
3. 평균과 분위수, 요청 수와 오류율 등 의미가 다른 지표를 섞지 않습니다.
4. 관측 사실과 가능한 원인 가설을 분리하고 가설마다 확인할 추가 측정을 적습니다.
5. 작은 표본·결측·이상치가 해석에 주는 영향을 밝히고 목표 충족 여부는 제공된 기준으로만 판단합니다.

## 결과 계약

- 지표 / 기준값 / 현재값 / 단위 / 표본 수
- 절대 변화 / 상대 변화 / 계산식
- 조건 차이와 비교 한계
- 원인 가설 / 지지·반대 관측 / 다음 측정
- 목표 기준 / 충족·미충족·미판정

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 상관된 시간 변화만으로 특정 코드가 원인이라고 확정하지 않습니다.
- 평균값만으로 모든 사용자의 체감이 개선되었다고 말하지 않습니다.
- 측정하지 않은 지표나 신뢰구간을 만들어 내지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 사실과 가설 분리.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
