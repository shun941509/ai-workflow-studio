# 상충 출처 사례집

문서 ID: ER-060 / 버전 1.0 / 기준일 2026-10-01

이 문서와 데이터의 기관 “한빛 업무연구소”, 제품 “라온 협업보드”, 역할·업무·기록은 모두 가상입니다. 실제 고객·개인·제3자 문서를 사용하지 않았습니다. 예시를 실제 서비스 정책이나 사건으로 오인하지 마세요.

## CONFLICT-01 원본 보존
sources.json은 6개 가상 원문을 개별 ID로 보존합니다. 동일 주제라도 적용 시점·범위가 다를 수 있습니다. 서로 다른 수치를 발견했다고 원문을 하나로 합치지 않습니다.

## C1
주제 export-notice; 범위 standard; 시행 2026-10-01~2026-10-31; 상태 approved.

표준 변경은 2일 전에 알린다.

## C2
주제 export-notice; 범위 standard; 시행 2026-11-01~종료 미정; 상태 approved.

표준 변경은 5일 전에 알린다.

## C3
주제 file-limit; 범위 Basic; 시행 2026-10-01~종료 미정; 상태 approved.

파일 하나의 한도는 20 MiB이다.

## C4
주제 file-limit; 범위 Team; 시행 2026-10-01~종료 미정; 상태 approved.

파일 하나의 한도는 100 MiB이다.

## C5
주제 support-window; 범위 all; 시행 2026-10-01~종료 미정; 상태 approved.

가상 지원 접수는 17시에 끝난다.

## C6
주제 support-window; 범위 all; 시행 2026-10-01~종료 미정; 상태 approved.

가상 지원 접수는 18시에 끝난다.

## CONFLICT-02 판정 순서
질문의 시점·범위를 확인한 뒤 두 출처의 상태·시행일·주장을 비교합니다. 명시된 기준으로만 해소하고, 같은 조건에서 다른 값을 말하면 양쪽 출처와 충돌을 그대로 남깁니다.

## CONFLICT-03 사례
CF-01·CF-04는 시행일로 해소됩니다. CF-02는 플랜 확인이 필요합니다. CF-03은 같은 범위·기간의 승인 원문이 충돌하므로 한쪽 시간을 임의로 고르지 않고 담당자의 원본 확인을 요청합니다. 모든 사례는 cases.json에 고정되어 있습니다.
