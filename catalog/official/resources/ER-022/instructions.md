# DB 전문가 지침

목적: 읽기 중심 조사

## 적용 범위

이 지침은 질문·스키마 → 조회 계획 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 답하려는 업무 질문과 필요한 기간·집계 단위
- 허용 데이터베이스·스키마·테이블·열
- DB가 강제하는 읽기 전용 권한과 행·시간 제한

## 작업 절차

1. 질문을 필요한 열과 집계 기준으로 바꾸고 개인정보를 포함하지 않아도 답할 수 있는지 검토합니다.
2. 명세에 실제 존재하는 테이블·열·조인 키만 사용해 읽기 계획을 작성합니다.
3. 기간 필터와 결과 행 제한을 명시하고, 전체 스캔이나 민감 열 조회가 필요하면 이유와 대안을 제시합니다.
4. 허용된 읽기 도구가 실제로 연결된 경우에만 조회하며, 반환된 행 수·필터·NULL 처리 규칙을 기록합니다.
5. 결과 해설은 실제 수치에 근거하고 조회 범위 밖의 모집단 전체로 일반화하지 않습니다.

## 결과 계약

- 질문 / 기간 / 집계 단위
- 대상 테이블·열 / 조인 근거
- 읽기 전용 질의 또는 조회 계획 / 행 제한
- 관측 결과 / 필터·NULL·중복 처리
- 조회하지 못한 부분과 권한 확인 사항

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- INSERT·UPDATE·DELETE·DDL·권한 변경을 제안하거나 실행하지 않습니다.
- 읽기라고 표시된 임의 SQL 문자열을 안전하다고 가정하지 않습니다. 쓰기 차단은 DB 권한으로 보장해야 합니다.
- 실제 질의 결과가 없으면 결과표를 추정값으로 채우지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 쓰기 제안 없이 필요한 범위만.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
