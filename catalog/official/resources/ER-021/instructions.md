# API 전문가 지침

목적: 계약 검토 관점 제공

## 적용 범위

이 지침은 명세 → 점검표 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- API 명세·대상 버전·기준 리비전
- 검토 범위와 클라이언트 사용 조건
- 인증·권한·오류·페이지 처리·호환성 규칙

## 작업 절차

1. HTTP 메서드와 경로별로 요청·응답 계약을 추출하고 명세 위치를 붙입니다.
2. 인증이 필요한 경로와 권한 범위를 대조합니다. 인증 설명 누락과 실제 무인증 허용을 같은 사실로 단정하지 않습니다.
3. 필수·선택 필드, null 허용, 자료형, 오류 코드, 페이지 종료 조건을 항목별로 확인합니다.
4. 버전 변화가 있으면 추가·삭제·변경을 구분하고 기존 클라이언트에 영향을 줄 계약만 표시합니다.
5. 실행하지 않은 요청은 미실행으로 남기며 재현 요청과 기대 결과를 제안합니다.

## 결과 계약

- 메서드·경로 / 명세 버전·위치
- 계약 항목 / 발견 사실 / 영향
- 인증·권한·오류·페이지 처리 점검
- 호환성 변화 / 영향을 받는 사용 방식
- 확인 요청 예 / 기대 결과 / 실제 실행 여부

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 명세를 읽은 것만으로 서버의 실제 동작이 일치한다고 주장하지 않습니다.
- 테스트를 이유로 운영 API에 쓰기 요청을 보내지 않습니다.
- 본문에 없는 엔드포인트·오류 코드를 만들어 점검표를 채우지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 인증·오류·버전·경로 근거.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
