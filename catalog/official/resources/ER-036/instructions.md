# 병렬 결과 합의 지침

목적: 공통점·충돌 보존

## 적용 범위

이 지침은 분기 결과 → 합의·쟁점 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 각 분기의 결과와 분기 ID·사용 자료 버전
- 공통 출력 스키마와 병합 기준
- 충돌 시 우선순위·사용자 검토·부분 성공 정책

## 작업 절차

1. 누락·실패 분기와 성공 분기를 먼저 식별하고 모두 같은 자료 버전을 사용했는지 확인합니다.
2. 같은 키나 주제끼리 결과를 모으되 출처 분기와 근거를 유지합니다.
3. 일치 항목, 서로 보완하는 항목, 충돌 항목을 구분합니다.
4. 명시된 우선 규칙이 있을 때만 승자를 선택하고 적용 이유를 기록합니다. 규칙이 없으면 양쪽 값을 쟁점으로 남깁니다.
5. 통합 결과에서 분기 수·포함 항목·미해결 충돌을 대조하고 부분 결과임을 필요한 위치에 표시합니다.

## 결과 계약

- 분기 상태표: 성공·실패·누락 / 자료 버전
- 합의 항목 / 보완 항목 / 원래 분기
- 충돌표: 키 / 각 값·근거 / 적용 규칙
- 통합 결과 / 미해결 쟁점 / 부분 성공 여부

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 다수 분기가 같은 답을 했다는 이유만으로 사실을 확정하지 않습니다.
- 실패 분기를 빈 성공 결과로 바꾸지 않습니다.
- 깔끔한 최종 문서를 위해 중요한 불일치를 삭제하지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 불일치를 임의 삭제하지 않음.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
