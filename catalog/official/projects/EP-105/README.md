# 연구 근거 목록 RAG

문헌 구간 정리. 연구 질문 → 근거 목록.

## 실행 준비

실제 JSON 응답 모델을 project-model에 연결하고 지원 기능이 있는 Studio Runner에서 운영 ZIP을 엽니다. 계정·키는 동봉하지 않습니다.

1. sample-input.json의 연구 질문과 검색 단어를 입력합니다.
2. 파일 선택에서 resources/practice/study-a.md와 study-b.md를 함께 선택합니다. 실제 작업에서는 사용 권한이 있는 UTF-8 문헌 원문으로 교체할 수 있습니다.
3. evidence와 interpretations, 실제 source ID·인용 범위·메타데이터 누락을 서로 대조합니다.

## 원문과 범위

두 연구 원문은 실제 논문이 아닌 원작 가상 기록입니다. UTF-8 TXT·Markdown·JSON을 최대 4개, 각각 64KiB까지 선택합니다. 실제 문헌의 메타데이터·권리·품질은 따로 확인해야 합니다.

원래 필수 블록 knowledge·retrieval·ai을 보존했습니다. 관리 파일에서 실제 키워드 색인을 만들며 검색 자료 전체를 AI reference 첨부로 우회하지 않습니다. IndexRef와 원문 해시·UTF-8 위치를 출력에 보존합니다. 현재 실행에 속한 색인만 사용합니다. 

## 결과와 수락 기준

1. SYN-R-A의 집단 중앙 시간과 SYN-R-B의 합계 평균을 각각 원문 관측으로 구분하고 지표·방법·한계를 함께 기록합니다. 가상 자료임을 숨기지 않습니다.
2. 원문 주장과 관측은 evidence.kind로 구별하고, 새로운 해석은 interpretations에 evidenceIds와 불확실성을 붙입니다. 없는 evidence ID 참조는 실패입니다.
3. 모든 citationId·quote는 실제 검색 목록과 원문 UTF-8 범위에 존재해야 합니다. 메타데이터가 없는 R-B 기록일·DOI는 null이고 가짜 출판·저자·페이지를 만들지 않습니다.
4. 관련 정렬 원문이 검색돼도 유의성 p값·모바일 결과·장기 효과가 없으면 insufficient_evidence로 유보합니다. 원문이 없다는 사실과 검색어가 맞지 않은 빈 결과를 구분합니다.
5. 분산·원시 값 없이 유의성이나 통합 효과를 만들지 않습니다. 실제 문헌 품질 판정·연구 재현·실제 모델 평가 통과를 주장하지 않습니다.

공통 완료 기준: 주장·해석 구분, 인용 위치 확인.

noSearchResults.status=no_search_results는 실제 검색 문맥이 비어 모델을 부르지 않은 결과입니다. 관련 문서가 검색됐지만 필요한 사실이 없는 answer.status=insufficient_evidence와 다릅니다. 키워드 검색은 의미·동의어·형태소 검색이 아니므로 빈 검색을 사실의 부재로 단정하지 않습니다. 모델의 의미 해석·주장과 근거의 일치 여부는 사람이 확인해야 하며 JSON 구조 검사가 이를 증명하지 않습니다. 

## 실패·한도·개인정보

실제 모델 미연결·파일 무결성 오류·잘못된 UTF-8·스키마 위반·예산 초과·취소는 오류로 남기고 성공 결과로 대체하지 않습니다. 모델 호출 최대 1회, 총 30,000토큰, 활성 10분입니다. 모델 호출 시 질문·검색 근거·지침이 연결한 공급자에 전송됩니다. 키워드 색인·검색에는 외부 embedding 호출이 없습니다. PDF·OCR·웹·외부 DB·Agentic 재검색·reranker·GraphRAG·실제 제품 조작을 제공한다고 주장하지 않습니다.

원본 파일·고정 버전 격리·실제 검색·3종 ZIP은 계정 없이 검증합니다. 실제 모델 답변·Codex·Claude Code·OpenCode 실제 사용·검수·게시는 unverified이며 usable/published로 세지 않습니다. 새 원작 입력은 실제 고객·실제 연구 데이터가 아니며 실제 모델 정답 파일은 없습니다. 내부 검증·개발 설치·fixture는 ZIP 밖에 있습니다.

사용·수정·재배포 조건은 LICENSE.md와 각 자료의 LICENSE.md입니다. 제3자 권리를 부여하지 않습니다. 생성기는 기존 폴더를 덮어쓰지 않으며 수정 시 원문·descriptor·카탈로그 해시와 수락 계획을 함께 재검토합니다.
