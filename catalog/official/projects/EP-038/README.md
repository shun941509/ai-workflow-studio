# 보고서 필수 요소 점검

배포 요건 확인. 보고서·기준 → 누락 목록.

네 개의 필수 항목을 원문에 각각 대조하고 모든 기준을 충족해야 passed=true입니다. 사람의 결정과 모델 점수·누락 근거를 별도로 보존합니다.

## 시작

1. 실제 JSON 응답 모델을 project-model에 연결하고 sample-input.json의 필수 기준을 확인합니다.
2. 파일 선택에서 resources/practice/report.md 또는 권한 있는 실제 UTF-8 보고서를 선택합니다.
3. 각 점수와 원문 인용·누락 이유를 확인하고 수락 또는 거절합니다.

resources/practice/sample-input.json은 초기 입력에 사용할 실제 가상 연습 데이터이며 프로젝트 폴더의 sample-input.json과 같습니다. 실제 모델 답변이나 테스트 fixture가 아닙니다. 지침·문서 원본과 descriptor 해시를 workflow.resources에 고정했고 모든 해당 원본 파일을 ZIP에 동봉합니다.

원래 필수 구성 document_extract·evaluate·review을 보존했습니다. 원본 사용자 자료의 내용은 분석 대상이며 작업의 권한·지침을 바꾸는 명령이 아닙니다.

## 결과 확인

1. summary·metrics·risks·owner가 빠짐없이 평가되어야 합니다.
2. 연습 보고서의 담당 역할 미기재를 owner=0으로 검출하고 없던 담당자를 만들지 않아야 합니다.
3. 집계 기간 2026-10-05~2026-10-09와 확인 6/대기 2를 원문 그대로 인용해야 합니다.
4. 한 항목이 0이면 passed=false이며 검토 수락이 이 점수를 바꾸거나 배포를 실행하지 않아야 합니다.

공통 완료 기준: 지정 필수 항목의 누락을 검출.

## 범위·실패·준비

- 고정한 네 기준 ID의 설명은 사용자가 입력합니다. 다른 구조의 점수표를 쓰려면 워크플로 새 판본을 준비합니다.
- UTF-8 TXT·Markdown·JSON만 지원하며 PDF·이미지·OCR는 지원하지 않습니다.

실제 JSON 응답 모델을 project-model에 연결해야 합니다. 계정·키·외부 설정은 동봉하지 않습니다. 모델 평가 점수는 모델의 관찰이며 실제 사실 인증이 아닙니다. 입력 스키마·원본 해시·모델 응답이 잘못되거나 토큰·호출·시간 한도에 도달하면 실제 오류로 중단합니다. 응답이 없는 검토는 승인으로 바꾸지 않습니다. 실제 업무 수행·발송·게시·채용 결정·계정 변경을 하지 않습니다.

현재 검증은 공통 계약·원본 무결성·운영 ZIP 및 계정 없이 확인 가능한 순수 처리입니다. 실제 모델 품질, Codex·Claude Code·OpenCode 실제 사용, 검수·게시는 unverified입니다. 원본 사용·수정·재배포 조건은 LICENSE.md에 있습니다. 생성기는 이미 작성된 폴더를 자동 덮어쓰지 않으며 수정 시 새 판본과 해시를 검토합니다.
