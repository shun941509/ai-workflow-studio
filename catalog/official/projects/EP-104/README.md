# 기술 문서 버전 RAG

버전 차이 설명. 질문·두 버전 → 차이·근거.

## 실행 준비

실제 JSON 응답 모델을 project-model에 연결하고 지원 기능이 있는 Studio Runner에서 운영 ZIP을 엽니다. 계정·키는 동봉하지 않습니다.

1. sample-input.json의 질문·검색어와 비교할 두 버전을 입력합니다. 1.0→2.0 및 2.0→1.0만 제공하며 같은 버전·알 수 없는 버전은 거절됩니다.
2. 두 원본을 관리 파일로 만든 뒤 부모가 버전별 파일 목록을 고정합니다. 병렬 자식은 파일 선택을 기다리지 않고 각자 독립 색인을 만듭니다.
3. searches.branches의 before/after 인용과 AI의 before/after 근거를 각각 대조합니다. 두 색인의 검색 점수를 합쳐 순위를 만들지 않습니다.

## 원문과 범위

이 예제를 위해 직접 작성한 가상 제품/API의 1.0·2.0 원문을 동봉합니다. 실제 서비스·기존 제품 문서라고 표시하지 않습니다. 지원 버전을 추가하려면 실제 원문과 선택 규칙·입력 계약을 함께 변경하고 새 판본을 검증해야 합니다.

원래 필수 블록 parallel·retrieval·ai·merge을 보존했습니다. 관리 파일에서 실제 키워드 색인을 만들며 검색 자료 전체를 AI reference 첨부로 우회하지 않습니다. IndexRef와 원문 해시·UTF-8 위치를 출력에 보존합니다. 현재 실행에 속한 색인만 사용합니다. 병렬 자식은 서로 다른 색인을 유지하고 검색 후보나 점수를 서로 합치지 않습니다.

## 결과와 수락 기준

1. before/after는 입력한 fromVersion/toVersion과 같고, 각각 별도 managed FileRef와 독립 IndexRef·generationId로 검색합니다. 반대 방향 비교도 같은 분리 규칙을 지켜야 합니다.
2. 1.0의 page/page_size·documents/updated_at·total_pages와 2.0의 cursor/limit·items/modified_at·next_cursor 차이는 각 버전의 실제 인용으로 확인합니다.
3. 한쪽에서만 검색되는 EXPIRED_CURSOR는 다른 버전에서 그 기능이 존재하지 않았다는 증거가 아닙니다. 해당 쪽의 빈 검색을 not_found_in_search로 드러냅니다.
4. 목록 문서를 검색해도 스냅샷 만료 시간의 수치는 없으므로 임의 숫자를 쓰지 않습니다. 양쪽 빈 검색은 모델 호출 없는 no_search_results입니다.
5. 각 비교의 인용 ID와 원문 UTF-8 위치가 올바른 버전 파일에 속해야 하며 다른 버전의 근거를 섞으면 실패입니다.

공통 완료 기준: 버전별 출처 구분.

noSearchResults.status=no_search_results는 실제 검색 문맥이 비어 모델을 부르지 않은 결과입니다. 관련 문서가 검색됐지만 필요한 사실이 없는 answer.status=insufficient_evidence와 다릅니다. 키워드 검색은 의미·동의어·형태소 검색이 아니므로 빈 검색을 사실의 부재로 단정하지 않습니다. 모델의 의미 해석·주장과 근거의 일치 여부는 사람이 확인해야 하며 JSON 구조 검사가 이를 증명하지 않습니다. 

## 실패·한도·개인정보

실제 모델 미연결·파일 무결성 오류·잘못된 UTF-8·스키마 위반·예산 초과·취소는 오류로 남기고 성공 결과로 대체하지 않습니다. 모델 호출 최대 1회, 총 30,000토큰, 활성 10분입니다. 모델 호출 시 질문·검색 근거·지침이 연결한 공급자에 전송됩니다. 키워드 색인·검색에는 외부 embedding 호출이 없습니다. PDF·OCR·웹·외부 DB·Agentic 재검색·reranker·GraphRAG·실제 제품 조작을 제공한다고 주장하지 않습니다.

원본 파일·고정 버전 격리·실제 검색·3종 ZIP은 계정 없이 검증합니다. 실제 모델 답변·Codex·Claude Code·OpenCode 실제 사용·검수·게시는 unverified이며 usable/published로 세지 않습니다. 새 원작 입력은 실제 고객·실제 연구 데이터가 아니며 실제 모델 정답 파일은 없습니다. 내부 검증·개발 설치·fixture는 ZIP 밖에 있습니다.

사용·수정·재배포 조건은 LICENSE.md와 각 자료의 LICENSE.md입니다. 제3자 권리를 부여하지 않습니다. 생성기는 기존 폴더를 덮어쓰지 않으며 수정 시 원문·descriptor·카탈로그 해시와 수락 계획을 함께 재검토합니다.
