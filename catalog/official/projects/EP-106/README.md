# 질문 분해 Agentic RAG†

복합 질문을 나눠 검색. 복합 질문 → 통합 답변.

## 시작

1. sample-input.json의 복합 질문을 입력합니다.
2. project-model에 gpt-5.4-mini-2026-03-17 대화·작업 연결을 명시적으로 선택합니다.
3. 파일 선택에서 delivery-policy.md와 return-policy.md를 함께 업로드합니다.
4. research.result의 delivery·returns·integratedAnswer와 research.citations의 서로 다른 원문을 대조합니다.

이 두 원문은 실제 상점 정책이 아닌 원작 가상 자료입니다. 실제 모델 답변·정답 fixture·키·개발 명령은 포함하지 않습니다. 키워드 검색은 로컬이지만 질문·문맥·선택 근거는 각 모델 토큰 확인·생성 요청에 전송됩니다. 외부 서비스 사용 비용이 발생할 수 있습니다. 근거 부족이면 답변을 유보합니다. 추가 질문·웹 검색·벡터·Graph 검색은 이 예제의 기능이 아닙니다.

## 설계 블록과 실제 연결

원래 설계: `agent·tool·retrieval·merge` / 등록 검색. 실제 운영 그래프는 input→file_input→merge(도구 인수)→tool(file.inspect)→knowledge→retrieval(문서 범위)→merge(색인 목록·문맥)→agent(agentic_rag)→guardrail→merge→output입니다. 원래 agent·tool·retrieval·merge를 실제로 사용합니다. tool은 현재 실행의 첫 원문 무결성·메타데이터를 확인하며 모든 파일은 knowledge에서 다시 검증합니다. retrieval은 문서 범위를 먼저 탐색합니다. Agentic의 하위 검색은 Runner 내부에 고정한 동일 키워드 검색 kernel이 수행합니다. tool 노드가 모델에게 임의 검색/MCP 권한을 주는 구조가 아닙니다.

범용 질문 분해의 첫 운영 예로 배송·반품 두 정책을 함께 묻는 질문을 다룹니다. resultSchema는 delivery와 returns를 각각 필수로 요구합니다. 다른 도메인·질문 구성으로 확장하려면 입력 안내·결과 스키마·원문·평가를 함께 바꾸세요. 무관한 질문을 두 정책 답변으로 억지 변환하지 않습니다.

## 결과 확인

1. 복합 질문에서 배송·반품 하위 질문을 실제로 생성하고 최소 두 하위 질의를 실행합니다. 한 부분이 누락된 answer JSON은 결과 스키마에서 거부합니다.
2. 배송 답변은 결제 확정 다음 영업일부터 2~4영업일, 반품 답변은 수령일부터 14일·미사용·원래 포장·구성품 조건을 각 원문과 대조합니다. 실제 정책이라고 표시하지 않습니다.
3. 두 문서의 실제 UTF-8 범위·원본 hash·IndexRef를 citation에서 확인합니다. 답변에 필요한 서로 다른 문서 근거를 골랐는지 실제 모델 검수에서 확인합니다.
4. 원문에 없는 비용·환급 일수·도착일 또는 어느 한 부분의 근거가 없으면 insufficient_evidence로 유보합니다. 관련 검색이 있다는 것과 필요한 사실이 있다는 것을 구분합니다.
5. 최대 3라운드·회당 2질의·12단계·30청크·누적 검색 문맥 6000토큰과 root 4모델 호출·30000토큰 한도를 넘지 않습니다. 실제 모델 사용량과 로컬 문맥 토큰은 구별합니다.

공통 완료 기준: 하위 질문 포함, 검색 한도 준수. guardrail은 답변 두 부분과 최소 2인용의 구조를 검사합니다. 서로 다른 문서인지, 각 답변이 근거에 의해 뒷받침되는지, 자연어 질문의 뜻을 모두 덮는지는 이 구조 검사만으로 보증되지 않으며 실제 모델 평가·사람 검토가 필요합니다. 선택된 인용의 ID·원본·권한은 Runner가 검증합니다.

research.status는 answered, insufficient_evidence, conflicting_evidence로 구분됩니다. 뒤의 둘은 result=null입니다. 유보 결과를 정상적으로 만든 run이 succeeded여도 완전 답변을 얻었다는 뜻은 아닙니다. 추가 질문(EP-107)이나 웹 최신성 확인(EP-110)을 했다고 표시하지 않습니다.

## 한도·실패·개인정보

파일은 UTF-8 TXT/Markdown 최대 4개, 각각 64 KiB입니다. 입력 자료·지침은 권한을 확장하는 명령으로 취급하지 않습니다. 색인은 현재 실행 안에서만 사용하고 권한 철회는 이후 모델 전송·결과 공개를 차단합니다. 토큰 확인 실패·사용량 불명·잘못된 모델/근거·예산 초과·원본 변조·취소를 가짜 성공으로 덮지 않습니다. 결과 불명은 예약을 보존하며 자동 재실행하지 않습니다. 원문을 모델의 reference 첨부로 직접 우회하지 않습니다.

키워드 검색은 의미·동의어·형태소 검색이 아니므로 빈 검색을 사실의 부재로 단정하지 않습니다. 운영 고정 모델과 계정은 사용자가 준비해야 하고 실제 모델 접근·응답 품질은 unverified입니다.
