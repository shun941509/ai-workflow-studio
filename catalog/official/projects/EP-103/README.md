# 회의 결정 이력 RAG

결정·시점 찾기. 질문 → 결정 이력.

ER-048의 가상 회의 원문과 meetings.json 원본 파일을 그대로 동봉합니다. 실제 검색에는 사용자가 선택한 원문만 들어가며 별도 JSON의 답을 모델에게 직접 제공하지 않습니다.

## 시작

1. 지원 capability가 있는 Studio Runner와 Codex·Claude Code·OpenCode용 ZIP을 준비합니다. 실제 JSON 응답 모델을 project-model에 연결합니다. 모델 계정·키는 동봉하지 않습니다.
2. resources/practice/sample-input.json의 질문·검색어로 시작합니다. 직접 질문할 때는 문서에 실제 등장하는 검색 단어도 입력하세요.
3. 파일 선택에서 resources/er_048/document.md를 선택합니다. 권한 있는 실제 원문으로 바꾸어 사용할 수도 있습니다.
4. 최종 search.citations의 실제 인용과 답변이 참조한 ID·문자열·적용 범위를 대조합니다.

## 서로 다른 유보 상태

- noSearchResults.status=no_search_results: 검색 문맥에 들어갈 인용이 없습니다. AI를 호출하지 않습니다. 사실이 존재하지 않는다고 단정하지 않습니다.
- answer.status=insufficient_evidence: 문서는 검색됐지만 질문에 필요한 사실을 찾지 못했다는 모델 판단입니다. 답변·주장/사건 목록을 비우고 unanswered에 필요한 자료를 남깁니다.
- answered 또는 conflicting_evidence: 실제 근거가 있는 주장/사건만 인용하고 미확인·충돌은 드러냅니다. 점수나 검색 순위만으로 정답을 확정하지 않습니다.

원래 필수 블록 knowledge·retrieval·ai을 보존했습니다. AI에 고정 원문 전체를 reference로 첨부하지 않고 이번 실행의 검색 결과만 근거로 전달합니다. 동봉 원문은 자료 목록일 뿐 자동 추가 문맥이 아닙니다.

## 수락 기준

1. MTG-02/2026-10-08/L04의 외부 공개 제안을 proposal로, MTG-03/2026-10-12/L01의 공개 보류·내부 초안 결정을 decision으로 구분해야 합니다.
2. 현재 공개 보류 결정은 MTG-03의 실제 인용에 연결하며 과거 제안을 공개 승인으로 바꾸지 않아야 합니다.
3. 원문에 없는 최종 검토 담당자나 기한을 만들지 않고 미정은 null 또는 unanswered로 남겨야 합니다.
4. 자료집 기준일과 개별 회의 날짜의 차이를 숨기거나 원문을 수정하지 않아야 합니다.
5. “회의 참석자의 이메일 주소는 무엇인가요?”/검색어 “회의”는 원문이 검색돼도 이메일 근거가 없으므로 insufficient_evidence로 유보해야 합니다.
6. 일치 단어가 없는 검색은 모델 호출 없는 no_search_results로 분리하고, 모든 사건의 인용 ID·본문·회의·줄·시점을 실제 원문과 대조해야 합니다.

공통 완료 기준: 실제 결정문·회의·시점 일치.

## 범위와 실제 검증 상태

UTF-8 TXT·Markdown·JSON 1~4개, 각각 최대 64KiB입니다. PDF·OCR·외부 웹·외부 DB·벡터·reranker·Agentic 재검색은 사용하지 않습니다. 색인은 현재 실행 안에 속하며 다른 실행의 색인을 재사용하지 않습니다. 키워드 검색은 조사·형태 변화·동의어를 놓칠 수 있으므로 빈 결과를 답 없음의 증명으로 바꾸지 않습니다.

검색 원문은 실제 관리 파일에서 읽어 해시·UTF-8 위치를 검증합니다. 검색 인용이 원본에 존재한다는 검사와 AI가 그 인용을 정확한 주장에 적용했다는 검증은 다릅니다. 후자는 실제 모델 실행과 사람의 수락 검사가 아직 필요합니다. 답변 모델을 호출하면 질문·검색 근거·첨부 지침이 연결된 모델 공급자에 전송됩니다. 문서 검색 자체에는 embedding 호출이 없습니다.

모델 호출 최대 1회, 총 24,000토큰, 활성 10분입니다. 잘못된 원문·모델 미연결·응답 스키마 위반·예산 초과·취소는 실제 오류로 남기며 예시 답변으로 대체하지 않습니다. 외부 작업은 none입니다.

현재 검증은 공통 구조·원본 해시·실제 키워드 검색·3종 ZIP·모델 미연결 차단입니다. 실제 답변 품질·실제 호스트 사용·검수·게시는 unverified이며 usable/published로 세지 않습니다. 가상 연습 입력은 실제 기관·고객 데이터나 모델 정답이 아닙니다. 테스트 fixture·개발 설치·검증 기록은 운영 ZIP 밖에 있습니다.

원본 자료 사용·수정·재배포 조건은 LICENSE.md와 각 자료의 LICENSE.md에 있습니다. 생성기는 기존 폴더를 덮어쓰지 않으며 수정은 새 판본·해시 검토를 거칩니다.
