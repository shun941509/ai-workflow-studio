# 제품 문제 해결 RAG

제품 버전별 절차 안내. 증상·버전 → 해결 안내.

## 실행 준비

실제 JSON 응답 모델을 project-model에 연결하고 지원 기능이 있는 Studio Runner에서 운영 ZIP을 엽니다. 계정·키는 동봉하지 않습니다.

1. sample-input.json에서 버전 1.0 또는 2.0, 증상과 원문 검색 단어를 입력합니다. 지원하지 않는 버전은 입력 단계에서 거절됩니다.
2. 선택된 고정 원문만 실제 관리 파일로 생성됩니다. 생성 파일과 search.index·citations를 확인합니다.
3. 실제 모델의 안내 초안이 나오면 review에서 버전과 인용을 직접 대조한 뒤 수락 또는 거절합니다.

## 원문과 범위

이 예제를 위해 직접 작성한 가상 제품/API의 1.0·2.0 원문을 동봉합니다. 실제 서비스·기존 제품 문서라고 표시하지 않습니다. 지원 버전을 추가하려면 실제 원문과 선택 규칙·입력 계약을 함께 변경하고 새 판본을 검증해야 합니다.

원래 필수 블록 knowledge·retrieval·ai·review을 보존했습니다. 관리 파일에서 실제 키워드 색인을 만들며 검색 자료 전체를 AI reference 첨부로 우회하지 않습니다. IndexRef와 원문 해시·UTF-8 위치를 출력에 보존합니다. 현재 실행에 속한 색인만 사용합니다. 

## 결과와 수락 기준

1. 1.0 선택은 BN-EXPORT-1.0 파일 하나만 생성·색인하고 2.0 분기는 skipped여야 합니다. 2.0 선택도 반대 방향으로 격리됩니다.
2. 1.0 EXPORT-10은 보관함→자료 내보내기·500행·CSV 근거를 사용해야 하고 2.0의 자료→내보내기 작업·2000행·JSON 절차가 섞이면 거절합니다.
3. 2.0 EXPORT-20과 EXPORT-21은 원문에 있는 서로 다른 절차를 구분합니다. EXPORT-21의 보장 대기 시간은 원문에 없으므로 답을 유보합니다.
4. 없는 검색어는 no_search_results이며 모델·검토를 호출하지 않습니다. 관련 문서가 있어도 필요한 사실이 없으면 insufficient_evidence입니다.
5. 검토자는 선택 버전·인용을 실제 확인하고 accepted/rejected를 기록합니다. 거절은 수락이나 문제 해결 완료로 바뀌지 않아야 합니다.

공통 완료 기준: 다른 버전 절차 혼입 없음.

noSearchResults.status=no_search_results는 실제 검색 문맥이 비어 모델을 부르지 않은 결과입니다. 관련 문서가 검색됐지만 필요한 사실이 없는 answer.status=insufficient_evidence와 다릅니다. 키워드 검색은 의미·동의어·형태소 검색이 아니므로 빈 검색을 사실의 부재로 단정하지 않습니다. 모델의 의미 해석·주장과 근거의 일치 여부는 사람이 확인해야 하며 JSON 구조 검사가 이를 증명하지 않습니다. review는 필수이며 accepted와 rejected 모두 원래 결정을 보존합니다. 검토 수락은 외부 작업 승인이나 문제 해결 완료 증거가 아닙니다.

## 실패·한도·개인정보

실제 모델 미연결·파일 무결성 오류·잘못된 UTF-8·스키마 위반·예산 초과·취소는 오류로 남기고 성공 결과로 대체하지 않습니다. 모델 호출 최대 1회, 총 30,000토큰, 활성 10분입니다. 모델 호출 시 질문·검색 근거·지침이 연결한 공급자에 전송됩니다. 키워드 색인·검색에는 외부 embedding 호출이 없습니다. PDF·OCR·웹·외부 DB·Agentic 재검색·reranker·GraphRAG·실제 제품 조작을 제공한다고 주장하지 않습니다.

원본 파일·고정 버전 격리·실제 검색·3종 ZIP은 계정 없이 검증합니다. 실제 모델 답변·Codex·Claude Code·OpenCode 실제 사용·검수·게시는 unverified이며 usable/published로 세지 않습니다. 새 원작 입력은 실제 고객·실제 연구 데이터가 아니며 실제 모델 정답 파일은 없습니다. 내부 검증·개발 설치·fixture는 ZIP 밖에 있습니다.

사용·수정·재배포 조건은 LICENSE.md와 각 자료의 LICENSE.md입니다. 제3자 권리를 부여하지 않습니다. 생성기는 기존 폴더를 덮어쓰지 않으며 수정 시 원문·descriptor·카탈로그 해시와 수락 계획을 함께 재검토합니다.
