# 부품 번호·증상 Hybrid RAG†

코드와 의미 동시 검색. 번호·증상 → 절차.

## 준비와 실행

1. 재순위 capability를 지원하는 Studio Runner에서 운영 ZIP을 가져옵니다. project-model은 실제 JSON 응답 대화 모델, rank는 재순위 전용 연결을 선택합니다. embed에는 OpenAI text-embedding-3-small, 256차원 계약에 맞는 임베딩 연결이 필요합니다.
2. rank의 고정 백엔드 계약은 openai-responses-rerank-v1 및 gpt-5.4-mini-2026-03-17입니다. 일반 대화 연결을 이름만 같다고 재사용하지 않습니다. 지원 화면에서 재순위 연결을 설정할 수 없다면 연결 준비 상태로 남겨 두고 지원 Runner 화면을 준비합니다. 키는 ZIP에 넣거나 호스트 대화에 붙이지 않습니다.
3. sample-input.json으로 시작하고 resources/practice/corpus의 원문 4개를 함께 선택합니다. 파일은 UTF-8 TXT·Markdown·JSON 최대8개, 각각8KiB입니다.
4. 결과 인용·출처와 실제 진행 기록의 rag.rerank 후보별 before/after·점수를 대조합니다. 원문 전체를 AI reference로 첨부해 검색을 우회하지 않습니다.

## 실행 계약

원래 필수 구성 knowledge·retrieval·ai / 융합·reranker을 보존했습니다. keyword와 vector 후보를 RRF로 융합한 뒤 재순위합니다. 각 단계의 점수는 다른 척도이며 합산하지 않습니다.

후보12개 이내→재순위→상위3개→문맥6000토큰 순서입니다. query와 후보 원문 합계64KiB를 넘으면 전송 전에 실패합니다. 재순위 점수는0~100의 관련성 판단이며 확률·정답 인증이 아닙니다. 전체 후보의 전후 순위는 실제 rag.rerank 이벤트에 있고 data.rerank에는 상태·fingerprint·inventoryHash·후보 수가 있습니다. 선택 후보의 stages는 단계별 점수를 보존합니다. AI가 숫자를 재작성한 표를 원본 순위 기록으로 사용하지 마세요.

## 수락 기준

1. 부품 번호와 증상을 한 질의로 보존하고 keyword/vector/RRF/reranker 단계를 구분해 기록합니다.
2. QX-120A의 QUEUE-HOLD는 등록 대기이며 QX-120B의 미리보기 지연·QX-102A의 날짜 조건·QX-210A의 전송 결과 불명과 섞지 않습니다.
3. 실제 정답 원문 구간이 top3에 회수되는지 고정 반례 세트로 평가하고, 모델 답변의 모든 단계가 정확한 부품의 인용인지 검사합니다.
4. 답변이 다른 부품 번호를 반환하면 identifier_mismatch로 보류합니다. 같은 번호를 반환해도 인용 적용의 정확성은 별도 실제 검증 대상입니다.
5. 미완성 번호·없는 장애·미기재 보장 시간은 유보하며 벡터 검색의 근접 후보를 정답으로 단정하지 않습니다.

공통 완료 기준: 정답 구간 상위 회수, 유사 코드 구분.

## 빈 검색·실패·외부 전송

빈 후보는 skipped_empty로 기록하고 재순위 모델을 호출하지 않습니다. 문맥에 인용이 없으면 no_search_results이며 답변을 생성하지 않습니다. Hybrid는 무관한 질문에도 가까운 벡터 후보를 반환할 수 있습니다. 후보가 있다고 근거가 충분한 것은 아니며 문서에 답이 없으면 insufficient_evidence가 필요합니다.

재순위 실패 정책은 fail입니다. 잘못된 모델·후보 ID·스키마·권한·원본 해시·예산·취소·결과 불명은 성공이나 원래 순위로 몰래 바꾸지 않습니다. 실제 응답을 확인할 수 없는 유료 호출은 미확정 상태로 남기며 자동 재시도하지 않습니다. 최대 모델 호출 12회, 총180000토큰, 활성15분을 공유합니다. 이는 비용 보증이 아닙니다.
