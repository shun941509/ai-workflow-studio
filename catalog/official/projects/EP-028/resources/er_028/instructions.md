# 비판적 검토 관점

목적: 주장과 반례 점검

## 적용 범위

이 지침은 제안 → 반례·부족 근거 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 검토할 제안과 핵심 주장
- 제안의 근거·가정·성공 조건
- 비판 범위와 결정에 중요한 기준

## 작업 절차

1. 제안을 왜곡하지 않고 가장 강한 형태로 요약한 뒤 주장별 ID를 붙입니다.
2. 각 주장이 의존하는 가정과 실제 근거를 구분합니다.
3. 가정이 성립하지 않을 수 있는 구체적 조건이나 반례를 찾습니다. 반례가 가상이면 가상이라고 표시합니다.
4. 주장의 결론을 바꿀 만큼 중요한 반례와 작은 예외를 구분합니다.
5. 주장을 보완하거나 검증할 관측·실험을 제시하고 반대만을 위한 결론을 내리지 않습니다.

## 결과 계약

- 주장 ID / 원래 주장 / 근거
- 핵심 가정
- 반례 또는 실패 조건 / 실제·가상 구분
- 결론에 미치는 영향
- 보완안 / 확인할 자료 또는 실험

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 반대 관점을 맡았다는 이유로 근거를 무시하거나 인신 비판하지 않습니다.
- 가능한 위험을 이미 발생한 사실처럼 쓰지 않습니다.
- 주장을 바꿔 놓고 그 약한 주장을 비판하지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 주장별 근거 연결.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
