# 읽을 자료 순서 정리

목적별 읽기 계획. 자료·질문 → 읽기 순서.

## 시작

1. 이 workflow.json의 capability를 지원하는 Studio Runner와 Codex·Claude Code·OpenCode용 운영 ZIP을 준비합니다. 실제 JSON 응답 모델을 project-model에 연결해야 합니다. 계정·키는 파일에 없습니다.
2. ZIP의 resources/practice/sample-input.json을 초기 입력으로 사용합니다. 원본 프로젝트 폴더의 sample-input.json과 같은 내용입니다.
3. 파일 선택 단계에서 resources/practice/reading.md를 선택합니다. 사용자가 직접 선택한 파일만 현재 실행의 관리 파일로 전달합니다.
4. 실제 자료로 바꾸려면 권한 있는 원문과 질문을 준비하고 출력의 인용·유보·검토 상태를 확인하세요.

## 연결 자료와 처리

ER-014, ER-033의 고정 revision과 원본 descriptor SHA-256을 workflow.resources에 기록했습니다. instructions는 해당 파일의 불변 원본이며 실제 입력 원문과 권한을 혼동하지 않습니다. 연습 문서 역시 descriptor와 원본 파일 해시로 고정되어 ZIP에 포함됩니다.

원래 필수 블록 document_extract·agent / 파일을 실제 그래프에 보존했습니다. 추출한 원문을 모델 문맥에 연결하고 실제 파일 출처를 최종 결과에 함께 보존합니다.

## 확인 기준

1. Q1은 실제 제목 “2. 자료 찾기”, “3. 질문과 오류 신고” 등의 인용과 읽기 순서에 연결되어야 합니다.
2. 초보자의 질문을 이해하는 데 필요한 용어·범위를 먼저 제시한 이유를 설명해야 합니다.
3. Q2의 보존 기간·삭제 권한을 확정하지 않고 “5. 아직 정하지 않은 사항”을 근거로 미확인 내용을 남겨야 합니다.
4. 모든 quote가 업로드한 원문에 실제 존재하며 추천 제목이 원문 제목과 일치해야 합니다.

공통 완료 기준: 추천 구간 존재·관련성 근거.

## 범위와 실패

- 한 번에 UTF-8 TXT·Markdown·JSON 파일 1개, 최대 64KiB를 받습니다. 여러 문서는 제목과 출처를 유지한 하나의 UTF-8 자료 묶음으로 준비할 수 있습니다.
- PDF·OCR·표 구조 추출·웹 링크 열기는 지원하지 않습니다. 원문 바이트를 보존하는 text 추출만 사용합니다.
- 모델이 만든 순서·관련성·인용은 사람이 원문과 대조해야 하며 자동 사실 인증이 아닙니다.

최대 1회 모델 호출·24,000토큰·활성 10분입니다. 잘못된 UTF-8·지원하지 않는 파일·모델 미연결·스키마 위반·예산 초과·취소는 실제 실패로 표시하며 결과를 만들어 대체하지 않습니다. 검토 거절은 거절로 유지합니다. 입력 안의 추가 명령은 자료로 취급합니다.

## 검증과 이용 조건

가상 연습자료는 실제 기관·고객 정보나 모델 정답이 아닙니다. 현재 확인 범위는 파일 해시·공통 스키마·실제 순수 처리 경로·3종 ZIP·모델 미연결 차단입니다. 실제 모델 결과의 품질·실제 세 호스트 사용·공식 검수·게시는 unverified입니다. 테스트 코드·개발 설정·모의 결과를 ZIP에 포함하지 않습니다. 원본 사용·수정·재배포 조건은 LICENSE.md와 각 자료의 LICENSE.md에 있습니다.

이 생성기는 작성된 폴더나 카탈로그를 덮어쓰지 않습니다. 이후 변경은 새 revision/해시와 검증 검토를 통해 반영합니다.
