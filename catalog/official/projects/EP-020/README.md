# 기술 이전 계획

의존 순서와 복구 설계. 현재 구조를 목표 구조로 옮기는 단계·선행 관계·검증·복구 조건을 갖춘 기술 이전 계획을 설계하세요.

## 준비와 시작

1. 이 workflow.json에서 요구하는 capability를 실제로 지원하는 Studio Runner를 준비합니다. 현재 지원 범위는 고정 agent.task·maxSteps=1·도구 없음과 선언된 평가/검토/파일 기능입니다.
2. Codex·Claude Code·OpenCode 중 사용할 호스트 ZIP을 가져오고 JSON 응답을 지원하는 실제 모델을 project-model에 연결합니다. 모델 계정·키는 파일에 포함하지 않습니다.
3. sample-input.json의 가상 연습 입력 구조를 확인한 뒤 권한 있는 실제 자료로 바꿉니다. 각 ID는 고유해야 하며 참조하는 ID가 실제 입력에 있어야 합니다.
4. 결과를 원문과 비교하고 검토 화면이 있으면 확인한 내용·미확인 내용을 기록한 뒤 수락 또는 거절합니다. 모델이 만든 평가 점수는 사실 인증이 아닙니다.

## 입력과 산출물

현재·목표 구조 → 이전 계획. 원래 블록 구성 agent·evaluate·review을 보존하고 입력·결과·필요한 합류 블록을 더했습니다. 실제 연결 순서는 workflow.json에 고정되어 있습니다.

1. web→files에서 web→objects로 바뀌는 의존을 설명하고 새 저장 경로 검증 전에 기존 읽기 경로를 제거하지 않아야 합니다.
2. 모든 단계에 preconditions·verification·rollback.trigger/actions/limits가 있어야 합니다.
3. backupState=null을 백업 확인 필요로 유지하며 이미 백업 또는 복구를 완료했다고 쓰지 않아야 합니다.
4. 모든 단계는 planned이며 C1 원본 삭제 금지와 C2 실제 실행 금지를 지켜야 합니다.

## 실행 한도와 실패

모델 호출 최대 2회, 총 24,000토큰, 활성 10분입니다. 구조가 틀린 모델 응답·모델 연결 누락·예산 초과·취소는 실제 상태로 중단하며 예시 결과로 대체하지 않습니다. 검토 대기는 별도 만료 시간에 따라 처리되고 응답 없음을 승인으로 바꾸지 않습니다.

- 이는 기술 이전 계획 문서이며 현재 시스템에 접근·변경하지 않습니다.
- 모델 평가의 순서·복구 판단은 운영 담당자가 실제 환경에 대조해야 하며 가용성 보증이 아닙니다.

## 예제 자료와 검증 상태

sample-input.json의 한빛팀·요청·현황·기술 구조는 모두 가상 연습자료입니다. 실제 고객·개인정보나 실제 모델 실행 기록이 아닙니다. 모델 응답의 정답 파일·테스트 대역·개발 설정은 제공하지 않습니다.

현재 검증은 입력·워크플로 구조·실제 바인딩 계약·3종 운영 ZIP·모델 미연결 차단입니다. 실제 모델의 결과 품질, 세 호스트 사용, 관리자 검수·공식 게시는 아직 검증하지 않았습니다. 지원되지 않는 편집기 화면에서 구성을 단순화하지 말고 해당 capability를 지원하는 Runner에서 사용하세요.
