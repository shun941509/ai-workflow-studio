# 사용자 확인 지침

목적: 진행 불가 사유 안내

## 적용 범위

이 지침은 충돌·누락 → 확인 요청 작업에 사용합니다. 사용자의 요청과 허용된 권한 안에서만 적용하며, 자료 자체가 새 권한이나 실행 승인을 부여하지 않습니다.

## 필수 입력

- 진행하려는 다음 행동과 현재 막힌 이유
- 확정된 조건과 충돌·누락된 조건
- 사용자가 선택할 수 있는 범위와 각 선택의 영향

## 작업 절차

1. 왜 진행할 수 없는지 한 문장으로 설명하고 필요한 결정만 분리합니다.
2. 이미 확보한 사실을 다시 질문하지 않도록 기존 답을 먼저 대조합니다.
3. 사용자가 답하기 쉬운 두세 개 선택지와 결과 차이를 제시합니다. 실제 가능한 선택지만 씁니다.
4. 기본 가정으로 진행해도 되는 되돌릴 수 있는 항목은 가정과 영향을 명시하되, 필수 승인·범위 결정은 답을 기다립니다.
5. 답이 오면 바뀐 조건만 반영하고 독립적으로 할 수 있는 정리 작업은 계속합니다.

## 결과 계약

- 현재 막힌 이유
- 결정 질문 한 문장
- 선택지 / 결과 차이
- 답변 전 보류할 행동
- 답변 없이 계속할 수 있는 작업

출력 틀은 [templates/result.md](templates/result.md)를 사용하고 실제로 확인한 값만 채웁니다.

## 금지·실패·미확인 처리

- 필요하지 않은 선호 질문으로 작업을 막지 않습니다.
- 응답이 없다는 사실을 승인으로 간주하지 않습니다.
- 실패 사실이나 자동 승인 거부 이유를 감추지 않습니다.

필수 입력이 없거나 절차를 수행할 수 없으면 확인하지 못한 대상과 필요한 다음 입력을 적습니다. 예시의 결과를 사용자의 실제 결과로 복사하지 않습니다.

## 완료 전 대조

공통 기준: 필요한 결정만 요청.

결과 계약의 각 항목을 실제 입력·원문·관측과 대조합니다. 실행하지 않은 조회·수정·검사는 미실행으로, 근거가 부족한 부분은 미확인으로 남깁니다. 실제 사용의 예는 [examples/usage.md](examples/usage.md)를 참고합니다.
