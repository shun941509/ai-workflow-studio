# 요구사항 reranker RAG†

긴 질의의 핵심 근거 선택. 요구사항 → 항목별 근거.

## 준비와 실행

1. 재순위 capability를 지원하는 Studio Runner에서 운영 ZIP을 가져옵니다. project-model은 실제 JSON 응답 대화 모델, rank는 재순위 전용 연결을 선택합니다. 이 프로젝트는 임베딩 모델을 요구하지 않습니다.
2. rank의 고정 백엔드 계약은 openai-responses-rerank-v1 및 gpt-5.4-mini-2026-03-17입니다. 일반 대화 연결을 이름만 같다고 재사용하지 않습니다. 지원 화면에서 재순위 연결을 설정할 수 없다면 연결 준비 상태로 남겨 두고 지원 Runner 화면을 준비합니다. 키는 ZIP에 넣거나 호스트 대화에 붙이지 않습니다.
3. sample-input.json으로 시작하고 resources/practice/corpus의 원문 6개를 함께 선택합니다. 파일은 UTF-8 TXT·Markdown·JSON 최대8개, 각각8KiB입니다.
4. 결과 인용·출처와 실제 진행 기록의 rag.rerank 후보별 before/after·점수를 대조합니다. 원문 전체를 AI reference로 첨부해 검색을 우회하지 않습니다.

## 실행 계약

원래 필수 구성 retrieval·evaluate·ai / reranker을 보존했습니다. 현재 실행의 keyword 후보를 요구사항별로 검색하고 재순위합니다. 각 항목은 부모의 고정 IndexRef를 받는 독립 자식 실행입니다. evaluate는 인용 존재·재순위 완료만 검사하며 의미적 정확성 판정이 아닙니다.

후보12개 이내→재순위→상위3개→문맥6000토큰 순서입니다. query와 후보 원문 합계64KiB를 넘으면 전송 전에 실패합니다. 재순위 점수는0~100의 관련성 판단이며 확률·정답 인증이 아닙니다. 전체 후보의 전후 순위는 실제 rag.rerank 이벤트에 있고 data.rerank에는 상태·fingerprint·inventoryHash·후보 수가 있습니다. 선택 후보의 stages는 단계별 점수를 보존합니다. AI가 숫자를 재작성한 표를 원본 순위 기록으로 사용하지 마세요.

## 수락 기준

1. 각 요구사항 ID와 배열 위치를 부모 입력에서 보존하며 항목별 검색·판단을 독립 자식 실행으로 기록합니다.
2. 채택된 180일 정책과 폐기된 365일 제안을 구분하고, 삭제 완료 24시간 보장처럼 없는 조건은 유보해야 합니다.
3. 각 실제 rag.rerank 이벤트에서 후보 ID·before/after rank·검증 점수·fingerprint를 대조합니다. topK 밖 후보의 after=null은 미선택이며 원래 순위를 지워서는 안 됩니다.
4. evaluate는 준비 상태만 판정합니다. 정답 구간 회수·판단 정확성은 고정 질문 세트와 원문 범위에 대한 실제 모델 검증으로 별도 평가합니다.
5. 빈 키워드 검색은 skipped_empty와 no_search_results로 끝나며 재순위·답변 모델을 호출하지 않습니다.

공통 완료 기준: 정답 구간·재정렬 전후 순위 기록.
