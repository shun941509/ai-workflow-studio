# 항목 일괄 태깅

분류표에 따라 태그 부여. 목록·태그 → 분류 목록.

한 번에 1~8개 항목을 동일한 고정 분류표로 분류하고 원문 ID·내용·분류 이유·미분류를 모두 유지합니다. 실제 자료를 수정하거나 외부 서비스에 태그를 쓰지 않습니다.

## 시작

1. 실제 JSON 응답 모델을 project-model에 연결합니다.
2. 고정 분류표를 확인하고 sample-input.json의 가상 문의 또는 권한 있는 실제 항목을 입력합니다.
3. 결과의 모든 원문 ID·허용 라벨·미분류를 확인한 뒤 수락 또는 거절합니다.

resources/practice/sample-input.json은 초기 입력에 사용할 실제 가상 연습 데이터이며 프로젝트 폴더의 sample-input.json과 같습니다. 실제 모델 답변이나 테스트 fixture가 아닙니다. 지침·문서 원본과 descriptor 해시를 workflow.resources에 고정했고 모든 해당 원본 파일을 ZIP에 동봉합니다.

원래 필수 구성 loop·classify·review을 보존했습니다. 원본 사용자 자료의 내용은 분석 대상이며 작업의 권한·지침을 바꾸는 명령이 아닙니다.

## 결과 확인

1. I1·I2·I3·I4가 입력 순서대로 각각 정확히 한 결과에 대응해야 합니다.
2. 로그인 문의는 access, 내보내기는 export, 편집 문의는 editing의 정의와 대조해야 합니다.
3. 점심 메뉴 질문은 분류 범위 밖이므로 unclassified로 남겨야 합니다.
4. 허용 라벨 외 결과는 스키마에서 거절하고 사람 거절 결정은 그대로 보존해야 합니다.

공통 완료 기준: 허용 태그만 사용, 미분류 보존.

## 범위·실패·준비

- 분류표는 resources/practice/taxonomy.json과 classify.labels에 함께 고정되어 있습니다. 실행 중 임의 라벨 추가나 자동 분류표 변경은 하지 않습니다.
- 모델의 태깅 품질은 원문과 대조해야 하며 실제 시스템에 태그를 등록하지 않습니다.

실제 JSON 응답 모델을 project-model에 연결해야 합니다. 계정·키·외부 설정은 동봉하지 않습니다. 모델 평가 점수는 모델의 관찰이며 실제 사실 인증이 아닙니다. 입력 스키마·원본 해시·모델 응답이 잘못되거나 토큰·호출·시간 한도에 도달하면 실제 오류로 중단합니다. 응답이 없는 검토는 승인으로 바꾸지 않습니다. 실제 업무 수행·발송·게시·채용 결정·계정 변경을 하지 않습니다.

현재 검증은 공통 계약·원본 무결성·운영 ZIP 및 계정 없이 확인 가능한 순수 처리입니다. 실제 모델 품질, Codex·Claude Code·OpenCode 실제 사용, 검수·게시는 unverified입니다. 원본 사용·수정·재배포 조건은 LICENSE.md에 있습니다. 생성기는 이미 작성된 폴더를 자동 덮어쓰지 않으며 수정 시 새 판본과 해시를 검토합니다.
