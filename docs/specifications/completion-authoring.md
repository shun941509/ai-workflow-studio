# R-08 완료 기준 작성 화면

운영 편집기의 `흐름 설정·추가` → **기본 흐름**에서만 완료 기준을 편집한다. 기존 `workflow.completion` v1 계약을 사용하며 별도 판정 스키마를 만들지 않는다. 실행 상태와 업무 기준 충족을 구분하고, 모든 선언 기준이 필수임을 설명한다.

## 명시적 편집

기존 프로젝트에 기준을 자동 생성하지 않는다. 사용자가 **결과 형식 기준으로 시작**을 누르면 현재 `workflow.outputs`를 독립적인 result_schema 기준으로 복사한다. 이후 결과 형식이나 기준이 바뀌어도 자동으로 서로 복사하지 않는다. `SchemaFields`로 형식·필수 항목·길이 등을 편집하며 형식 통과가 사실 정확성이나 의미 품질을 보장하지 않는다고 안내한다.

기준마다 안정적인 ID, 설명, 기준 종류, 실제 확인 대상이 있다. 설명은 공백만 허용하지 않으며 최대 200자다. ID는 내부적으로 고유하게 생성하고 설명 변경으로 바꾸지 않는다. 기준은 1~32개이며 추가·수정·삭제 모두 공통 선언 검증을 통과해야 한다. 마지막 기준은 삭제하지 않는다. 업무 정의가 없는 경우 별도 **완료 기준 해제** 확인을 거쳐 선언을 제거하고 이후 실행을 업무 완료 미평가로 돌릴 수 있다. 업무 정의가 있으면 해제를 거절한다.

## 실제 블록 선택

| 기준 | 선택 가능한 실제 루트 블록 |
| --- | --- |
| result_schema | 최종 결과의 별도 사용자 스키마 |
| review_accepted | 루트 사용자 검토 |
| evaluate_passed | 현재 편집기가 지원하는 유효한 비어 있지 않은 규칙 평가 |
| agentic_answered | 현재 keyword/abstain 제한 설정 검증을 통과한 검색 에이전트 |
| loop_condition_met | 실제 로컬 본문과 유효한 종료식을 가진 until 반복 |

하위 흐름의 동명 블록, 중복 ID, 존재하지 않는 블록, 미지원 모드는 새 대상으로 선택할 수 없다. 일반 Agent task, Agentic 추가 질문, foreach, 모델 평가를 다른 기준으로 조용히 바꾸지 않는다. 반복 노드의 일반 작성 폼 확대는 별도 작업이며 이 참조 선택 기능이 해당 폼까지 제공한다는 뜻은 아니다.

삭제되거나 ID가 바뀐 원래 참조는 **확인 필요**로 남기고 자동 대상을 선택하지 않는다. 표시 이름 변경은 같은 ID의 최신 이름을 보여 준다. 깨진 참조가 여러 개라도 하나씩 수정·삭제할 수 있으며 남은 원래 오류를 숨기지 않는다. 내보내기는 기존 전체 Schema/core/editor 검사에서 차단한다.

## A02 초기 연결과 원자적 저장

**기존 규칙 검사·사용자 검토 함께 연결**은 사용자가 두 실제 블록을 선택했을 때 해당 완료 기준을 함께 추가한다. 이미 같은 근거가 연결되어 있으면 중복 추가하지 않는다. 노드 설정·검사 조건·질문·입출력·제어 경로·모델 결과는 수정하지 않는다. 자동 보완이나 재실행, 하위 흐름의 사용자 대기는 포함하지 않는다. 따라서 전체 R-08 또는 자동 보완 하네스가 완료됐다고 주장하지 않는다.

`completion-authoring.ts`의 `applyCompletionEdit`는 전체 워크플로의 불변 스냅샷을 반환한다. `FlowInspector.onWorkflowChange(change)`는 메인 초안의 `commit` 한 번으로 저장하며 기존 undo/redo·브라우저 복구 경계를 그대로 쓴다. 레이아웃은 `normalizeLayout`으로 기존 위치를 유지하면서 새 문맥 노드나 삭제된 노드에 대응한다.

명시적인 기준 편집 시에만 기존 업무 정의의 `task.criterionIds`를 전체 기준 ID와, `harness.accept`를 실제 전체 근거 노드 집합과 동기화한다. 다른 Task 내용·자료·권한은 변경하지 않는다. 이미 workingContext를 사용하면 **기존 구조의 정합성을 먼저 검사**한 후 같은 maxBytes로 preset을 다시 적용해 파생 `businessTask` literal을 갱신한다. request 연결·불투명한 지침·제어 경로·한도는 보존하며 조작된 문맥 구조를 자동 수리하지 않는다. 없던 workingContext를 이 화면에서 자동 도입하지 않는다.
