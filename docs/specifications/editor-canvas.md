# 캔버스 보기와 배치 보존

캔버스 이동·배율은 편집 화면 정보다. 이 기능은 workflow의 블록·연결·참조·실행 순서를 변경하지 않는다.

## 보기 규칙

- 블록 수·설정·측정 크기 변경은 전체 보기의 실행 조건이 아니다. 사용자 이동·배율을 유지한다.
- 최초 열기에는 저장된 흐름별 viewport를 우선 복원한다. 저장값이 없으면 작은 배치만 최대100%, 최소85%로 맞춘다. 그보다 작아지는 배치는 선택/시작 블록을100%로 보여 준다.
- `전체 보기`는 사용자가 누를 때만 전체 배치를 계산한다(30~100%). 매우 큰 배치는 최소 배율 때문에 한 화면에 모두 들어오지 않을 수 있으며 지도·이동으로 탐색한다.
- `선택 블록 보기`, 블록 선택 드롭다운, 오류 항목 이동, 캔버스에서 Enter/Space로 선택한 블록은 최소100%의 읽기 배율로 표시한다. 이미 보이고 읽을 수 있는 블록은 불필요하게 이동하지 않는다. 명시적 선택 블록 보기 버튼은 중심을 맞춘다.
- 새 클릭 블록은 현재 보이는 영역에서 빈 위치를 우선 찾는다. 빈 자리가 없으면 가까운 빈 위치에 추가하고 그 블록만 보여 준다. 기존 블록 위치와 읽기 가능한 사용자 배율을 유지한다.
- 끌어 놓기는 놓은 좌표를 그대로 사용한다. 카드 이동·드롭·설정 변경 후 자동 전체 보기를 실행하지 않는다.
- 툴바·상단 제목·하단 안내 공간을 계산에서 제외한다. 매우 큰 카드의 높이가 사용 가능한 영역을 넘으면 글자를 축소하는 대신 카드 위쪽을 보여 준다.

새 프로젝트 또는 위치가 전혀 없는 자료는2열 기본 배치다. 기존 유효 좌표는 순서와 거리에 관계없이 보존한다. 일부 위치만 없으면 기존 위치를 모두 수집한 다음 빈 자리에 누락 블록만 둔다. 대규모 기존 설계의 자동 재배치 기능은 제공하지 않는다.

## 저장 형식과 복구

기존 `editor.json`의 `schemaVersion:1.0.0`, `positions`, `subflows[id].positions/name`에 선택적 `viewport`만 추가한다. 실행 JSON Schema는 변경하지 않는다.

```json
{
  "schemaVersion": "1.0.0",
  "positions": { "start": { "x": 70, "y": 170 } },
  "viewport": { "center": { "x": 400, "y": 250 }, "zoom": 1.15 },
  "subflows": {
    "flow_1": {
      "name": "문서 정리",
      "positions": { "input": { "x": 70, "y": 170 } },
      "viewport": { "center": { "x": 180, "y": 240 }, "zoom": 1 }
    }
  }
}
```

`center`는 캔버스 중앙이 가리키는 설계 좌표다. 모니터·창 크기가 달라져도 같은 위치와 배율을 복원한다. 좌표는 유한수·절댓값100만 이하, 배율은0.3~1.5다. 저장된 유효 화면이 빈 공간을 가리켜도 임의로 재설정하지 않는다. 선택 블록 보기로 돌아올 수 있다.

이동 종료 때 저장하지만 문서 undo 이력은 추가하지 않는다. 문서 undo/redo는 이전 내용·카드 위치를 복구하면서 현재 흐름별 viewport를 유지한다. 흐름별 선택은 세션 메모리에서 격리한다. 재열기는 기본 흐름에서 시작하며 하위 흐름의 viewport와 한글 이름은 남는다. 삭제된 흐름의 저장 배치와 세션 선택은 제거한다.

## 외부 가져오기와 로컬 복구의 구분

`normalizeLayout`은 이전 브라우저 초안 복구용이다. 유효한 좌표·지원하는 viewport는 보존하고 잘못되거나 누락된 위치만 보정한다. viewport가 없던 이전 표준 ZIP도 열 수 있다.

`validateImportedLayout(value, workflow)`는 외부 복사 경계다. `{}`와 알려진 누락 필드는 허용한다. 알 수 없는 필드·블록 ID·흐름 ID·schemaVersion, 잘못된 좌표·이름·viewport는 오류로 반환한다. 이름이 유효하면 이전 편집기의 공백/정규화 형태도 그대로 돌려준다. 지원하지 않는 메타데이터를 버리고 복사 성공으로 처리하지 않는다. 호출자는 원본을 유지하고 실패를 안내해야 한다. 임의 도구의 `viewport:{x,y,zoom}` 형식은 이 centered viewport 계약과 다르므로 자동 변환하지 않는다.

## 키보드와 검증

툴바는 이름 있는 네이티브 버튼·배율 표시·focus outline을 사용한다. React Flow의 키보드 노드 선택과 화면 이동을 사용하되 캔버스 노드에서 Enter/Space 선택 시 오른쪽 설정과 읽기 배율을 함께 맞춘다. 폼 입력을 가로채는 전역 줌 단축키는 추가하지 않는다.

- `tests/editor/canvas-navigation.test.ts`: 임의 기존 위치·누락 보정·엄격 import·하위 격리·undo·창 크기 변화·실제3ZIP 보존.
- `tests/e2e/canvas-navigation.spec.ts`: 실제 Chrome1280/1440 화면에서5/15블록, 선택 글자 크기, 추가·undo/redo, 키보드, 흐름 왕복/재열기/창 크기 변화, 실제3ZIP, 드롭·카드 이동.
- 기존 하위 흐름·RAG 편집기 회귀도 함께 확인한다. 실키·모델 호출·외부 서비스 변경은 없다.

작은 화면의 데스크톱 편집기 가로 스크롤은 기존 제약으로 남는다. 이 변경은 전체 편집기를 모바일 레이아웃으로 재설계하지 않는다.
