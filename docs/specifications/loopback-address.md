# Runner 로컬 주소 선택

`apps/runner/src/local-api/listen-loopback.ts`는 실제 HTTP 서버 소켓을 `127.0.0.1`에 바인딩한 뒤 브라우저에서 사용할 수 있는 포트인지 확인한다. 임시로 빈 포트를 확인한 후 다시 여는 방식은 사용하지 않는다.

이 PC에서 읽기 전용 `netsh int ipv4 show dynamicport tcp` 조회 결과 동적 범위는 1024~15000이었다. 따라서 기본 `listen(0)`도 Fetch가 거부하는 포트를 선택할 수 있다. 기존 RAG 통합 시험의 `bad port` 실패는 재실행만으로 감출 문제가 아니라 설치된 Runner의 브라우저 접속에도 영향을 주는 결함이었다. 사용자 시스템의 포트 범위는 변경하지 않았다.

차단 목록은 [WHATWG Fetch §2.9](https://fetch.spec.whatwg.org/#port-blocking)의 2026-10-19 기준 표를 따르며 저장소에 명시한다. 자동 선택 포트가 목록에 있으면 아직 공개하지 않은 소켓을 닫고 최대32회 재선택한다. 명시적으로 지정한 금지 포트는 시작 전에 거부한다. 주소 점유·권한 등 실제 bind 오류는 다른 포트로 숨기지 않고 그대로 실패시킨다. Origin·Host 검사는 최종적으로 예약한 주소만 사용한다.

검증은 실제 소켓/HTTP 연결, 금지 포트의 시작 전 거부, OS 할당 결과를 통제한 close/rebind, 재선택 횟수 제한, 명시 주소 점유 오류와 listener 정리를 포함한다. 브라우저별 추가 정책·회사 프록시 전체의 호환성 보증은 아니다.
