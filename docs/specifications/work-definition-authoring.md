# 선택한 업무 정의 편집

기본 흐름의 설정에서 `업무 완료 기준` 다음에 `업무 정의와 사용할 자료`를 제공한다. 기존 블록 31종을 늘리지 않으며 기존 workflow JSON·초안 이력·운영 ZIP을 사용한다.

## 명시적인 작성

완료 기준과 실행 가능한 루트 AI 작업/단일 작업 에이전트가 있어야 `업무 정의 추가`를 사용할 수 있다. 클릭 전에는 기존 프로젝트에 업무 정의나 완료 판정을 자동으로 만들지 않는다. 추가한 초안의 파트너 목적·역할·업무 목표를 사용자가 구체화한다. 기본 문구는 편집용 업무 정의이며 검증된 전문성·완성된 Avatar를 뜻하지 않는다.

업무에 연결된 자료 중 이번 문맥에 포함할 지침·문서·Skill을 고르고 용도와 필수 여부를 기록한다. 필수 자료는 필수 설정을 먼저 해제해야 제외할 수 있다. 제외된 선택 자료도 Task의 고정 참조·용도·원본 버전은 보존한다. **문맥에서 제외**는 해당 모델 요청에 첨부하지 않는다는 뜻이며 ZIP에서 원본을 삭제한다는 뜻이 아니다. 계정 자료 전체를 자동으로 조회하거나 추가하지 않는다.

## 기존 블록으로 문맥 구성

`문맥 구성 적용`은 `applyWorkingContextPreset`을 사용한다. 기존 수행 블록의 단일 선행 경로에 이름별 묶기 merge를 삽입하고 선택 자료를 명시적 역할로 연결한다. 원래 문맥은 `context.request`, 업무 정의는 `context.businessTask`가 된다. 불투명한 기존 지침 문자열을 자동 치환하지 않으므로 경로를 사용하는 지침은 사용자가 직접 수정하도록 안내한다.

업무 정의나 자료 선택을 편집한 뒤 `문맥 구성 새로 반영`으로 고정 메타데이터·첨부를 맞춘다. 오래된 메타데이터와 선택 불일치는 ZIP/실행 준비에서 막힌다. 이미 만든 merge에 다른 블록이 의존하면 자동 해제를 거부한다. `문맥 묶기 해제`는 원래 요청 연결을 복구하고 선택 자료·업무 정의를 남긴다. 원래 context가 없던 경우 null 문맥이 남을 수 있으며 지침은 자동으로 되돌리지 않는다. 그 뒤 업무 정의를 해제할 수 있다.

기존 블록 배치는 유지하고 새 블록은 비어 있는 위치에 놓는다. 전체 변경은 한 초안 이력으로 저장하여 undo/redo, 주소 재열기, 기본/하위 흐름 전환에서 일관성을 유지한다. 하위 흐름에서는 업무 정의를 편집하지 않는다.

## 검증과 남은 범위

내부 confirmed: 작성 helper 4개와 문맥 공통 계약 18개, 관련 자료 정리/업무 정의를 포함한 4파일60시험 통과. 실제 Chrome에서 명시적 추가·문맥 삽입/해제·undo/redo·새로고침·동일한 3종 운영 ZIP을 확인했다(최종 단일 시나리오18.9초). 원문 자료 제외 후에도 고정 참조가 편집기의 자동 정리에서 삭제되지 않는 회귀를 포함한다.

운영 production 재빌드 통과 후 신규 4개/기존 하위 흐름4개, 총 **8개 실제 Chrome 시험 통과**(40.4초, `test-results/avatar-authoring-production`). 실제 모델·호스트 품질과 계정 저장은 이 시험의 증거가 아니다. Runner 문맥 원장·완료 판정·첫 회의 예제까지 연결한 수직 검증은 R-07~09에서 별도 기록한다. R-08의 자동 보완과 자식 대기는 아직 지원 완료로 표시하지 않는다.
