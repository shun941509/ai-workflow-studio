# 하위 워크플로 편집 계약

이 문서는 운영 편집기의 21번째 블록인 `subworkflow`와 프로젝트 내부의 이름 있는 흐름 편집을 정의한다. 외부 패키지 흐름, 반복, 병렬, 팀, 후보 탐색을 편집 가능하다고 표시하지 않는다.

## 실행 데이터와 화면 데이터

- 기존 `Workflow.subworkflows[flowId]`의 `FlowDefinition`을 그대로 사용한다. `entryNodeId`, `inputs`, `outputs`, `nodes`, `edges`만 흐름에 귀속된다. 모델 프로필·자료·정책은 프로젝트 전체에서 공유한다.
- 호출은 `config.flowRef={kind:"local",flowId}` 및 필수 `inputBindings.input` 하나다. 전달할 객체 전체 또는 값을 명시적으로 연결한다. 하위 흐름의 `inputs`는 전달한 값의 계약이며 루트 입력을 자동 상속하지 않는다.
- 호출 결과는 하위 흐름의 최종 `NodeOutput` 그대로다. `/data`는 하위 `outputs`에 맞는 값이고 `/data/result`라는 임의 포장을 만들지 않는다. 바인딩 선택기는 선언한 결과 항목만 제안한다.
- `editor.json`의 기존 `positions`는 루트 위치로 유지한다. 추가 `subflows[flowId].positions`에 각 하위 흐름 위치를 저장한다. 실행 JSON에 위치·선택 상태를 넣지 않는다. 기존 초안은 기본 위치로 정규화한다.

## 편집 동작

상단 흐름 선택과 흐름 설정을 제공한다. 새 흐름은 중복·예약 이름을 허용하지 않으며 입력→최종 결과의 유효한 전달 흐름으로 시작한다. 흐름 설정 및 입력/출력 블록의 폼은 동일한 `inputs`/`outputs`를 편집한다. 호출 설정에서 고정 흐름을 선택하고 해당 흐름으로 이동할 수 있다.

흐름 전환은 선택·측정값·연결 선택을 초기화한다. 노드 ID는 흐름 내에서만 고유하므로 검사 결과의 `instancePath`로 흐름을 구별하고 해당 화면과 노드로 이동한다. 검증 형식에 별도 `flowId` 필드를 추가하지 않는다.

흐름 이름은 한글·공백을 포함한 1~80자의 표시 이름으로 입력한다. `editor.subflows[id].name`에 보존하고 실제 FlowRef 식별자는 안정적인 영문 ID로 유지한다. 이름 변경은 참조·실행 정의를 바꾸지 않는다. 저장·undo/redo·ZIP에서도 표시 이름을 보존한다. 기존 표시 이름 없는 JSON은 ID를 이름으로 사용한다. 실행 정의의 subworkflows 키는 FlowRef.flowId와 같은 pattern으로 검증하여 `/`, `~`가 포함된 참조 불가능 이름과 모호한 검사 경로를 거절한다.

삭제 전 전체 프로젝트의 정식 FlowRef 필드를 검사한다. 지원하지 않는 블록의 참조도 삭제를 막는다. 참조를 먼저 해제해야 하며 호출 노드를 몰래 변경하지 않는다. 자료 핀 해제는 화면에 보이는 노드가 아니라 전체 프로젝트의 사용처를 기준으로 한다.

실행 설계와 모든 흐름의 위치를 포함하는 단일 초안이 저장·되돌리기·다시 실행의 단위다. 계정 저장과 운영 ZIP은 그 전체 스냅샷을 보존한다. JSON 가져오기는 지원 타입으로 된 하위 흐름을 허용하되 의미 오류는 표시하고 다운로드를 막는다.

## 안전한 준비 상태

클라이언트와 ZIP 경로가 같은 전체 흐름 `editorSupportIssues` 검사를 사용한다. core는 없는 참조·재귀·깊이 초과·흐름별 연결·입력 참조를 검사한다. 미사용 하위 흐름에도 숨은 미지원 모드를 허용하지 않는다.

현재 Runner 제약에 따라 하위 흐름의 `review`, `form.request`, 빈 파일 목록으로 선택을 기다리는 `file_input`은 다운로드를 막는다. 파일은 루트에서 선택한 뒤 명시적으로 전달한다. 모델·권한·예산은 루트 실행 한도를 공유하며 화면 전환이 별도 실행 권한을 부여하지 않는다.

## 완료 검증

1. 같은 노드 ID를 사용하는 두 흐름의 노드·연결·위치를 독립 수정한다.
2. 추가·참조중 삭제 차단·참조 해제 후 삭제·전체 초안 undo/redo·재열기를 확인한다.
3. 하위 입력/출력 폼과 명시 입력 바인딩, `/data`의 선언 결과 선택을 확인한다.
4. 하위 오류 이동, 재귀·없는 참조·깊이·숨은 미지원 모드의 실패 폐쇄를 검사한다.
5. 공유 자료가 다른 흐름에서 사용되면 핀을 보존하고 마지막 사용처 제거 때만 해제한다.
6. 세 호스트 ZIP에서 실제 workflow/editor 바이트를 검사하고 기존 Runner 하위 실행 회귀와 함께 확인한다. 실제 유료 모델 호출은 하지 않는다.
7. 실제 Chrome에서 폼·흐름 전환·저장/재열기·ZIP 다운로드와 좁은 화면을 검증한다.
