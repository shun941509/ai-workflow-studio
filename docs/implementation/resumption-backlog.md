# R-01~R-32 개발 재개 원장

사용자가 통합 계획을 기준으로 개발·검증·기록을 계속하도록 재승인했다. 기존 변경을 보존하며 P1/P2/P3/P4/E 요구를 대체하지 않는다. `소스 구현`, `내부 시험`, `실제 외부 연동`, `공식 게시`는 각각 집계한다. 내부 성공을 외부 연동/게시 성공으로 승격하지 않는다. 아래 표의 미착수는 기존 코드가 전혀 없다는 뜻이 아니라 해당 재개 작업의 완료 판정 전이라는 뜻이다.

## 진행 규칙

- 선행이 준비된 작업의 구현 → 영향 시험 → 통합 → 기록을 마치고 다음 작업을 진행한다. 계정이 필요한 시험만 준비 필요로 남기고 독립 작업은 계속한다.
- Schema/생성물/루트 manifest/lock 및 통합 기록은 통합 담당자 한 명이 소유한다. 독립 담당자는 명시한 파일만 수정한다.
- 검사 결과는 confirmed/partial/unverified/failed로 기록하며 명령·시점·대상 소스/산출물을 연결한다. skip은 통과가 아니다.
- 사용자 제품에는 운영 기능만 포함한다. 내부 시험 대역은 tests 밖으로 배포하지 않는다. 공개 함수·상태·권한·경로·승인 경계에 주석을 작성한다.
- 필수 개발·검증 완료 후 승인된 Git commit/push를 수행한다. 실제 서비스 게시/배포·계정/키 생성은 별도이며 개발 완료를 위해 조기 push하지 않는다.
- 공식 120+120 게시가 필요한 정식 출시 gate는 유지한다. 개발 완료/게시 준비/실제 출시를 구분하여 push와 게시의 순환 의존을 만들지 않는다.

## Avatar 설계 범위

Avatar는 표시용 아이콘이 아니라 Work Assets + Harness + Agent Capabilities를 결합한 업무 파트너다. Card/Role/Task는 업무 정의이며 Task에 Skill을 연결한다. 업무 자산/개인 실행 설정/세션 상태를 분리한다. Skill은 권한을 부여하지 않는다. A-01/02/04는 기존 실행 블록의 preset부터, A-03/05는 별도 계약이 필요할 때 전용 타입을 검토한다. 5개 후보를 곧바로 5개 새 타입으로 추가하지 않는다.

## 외부 준비

[연결 준비 안내](connection-setup.md)에 따라 사용자 소유 Supabase/Auth/Storage, 실제 모델 연결, 세 호스트 인증 및 깨끗한 Windows 시험 환경이 필요하다. 키를 채팅·명령 인수·로그·Git·ZIP에 전달하지 않는다. 준비되지 않은 연결은 준비 필요로 유지한다. 공식 서명/게시·서비스 배포는 준비된 후보 검토 뒤 별도 승인 범위다.

## 실행 증거

- 재개 기준: 기존 변경 보존, `main`의 작업 트리에서 검증. `node tooling/run-pnpm.mjs check:generated` 종료0, 전체 `typecheck` 종료0. 전체 Vitest 진행 중. 이 기록은 이후 수정 전체를 검증했다는 뜻이 아니다.
