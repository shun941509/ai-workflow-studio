# 진행 상태와 검증 기록

기준일: 2026-10-28 KST. 사용자 승인에 따라 P2 상세 계획과 후속 계획을 기록한 뒤 실제 구축·테스트를 진행한다. 코드 구현과 실제 외부 서비스 인증을 구분하며 정식 출시 완료를 주장하지 않는다.

후속 승인: 사용자는 개발 완료 후 git push를 요청했다. 현재 `main`, 원격 `origin`은 `https://github.com/shun941509/ai-workflow-studio.git`이다. 구현·검증 완료 후 커밋·push하며 미완성 상태를 먼저 올리지 않는다. 서비스 배포·유료 계정/키 생성 승인은 포함하지 않는다.

라이선스 결정: 사용자는 2026-10-28 자체 서비스 코드·Studio Runner를 MIT 오픈소스로 선택했다. 루트와 자체 패키지 8개에 원문 및 선언을 반영했다. 제3자·자료별 고지는 원본을 유지한다.

## 계획

P1 원문 상세 규격, 240개 공식 예제 원문 목록, 통합 작업 목록을 보존했다. P2-01~11의 대상 파일·순서·의존·검증·완료 조건은 P2-detailed-spec.md에 있고, P3/P4/E/출시는 P3-P4-catalog-plan.md에 있다. 추가 결정은 개별 규격 문서에 기록한다. [P2 실제 파일 대조](P2-verification.md), [제품 전체 출시 검사](release-gates.md).

사용자는 설명 전용 정지를 해제하고 [R-01~R-32 재개 원장](resumption-backlog.md)에 따라 구현·검증을 계속하도록 승인했다. 기존 미커밋 변경을 보존하며, 필수 개발·검증 완료 전 조기 commit/push는 하지 않는다. Avatar는 Work Assets + Harness + Agent Capabilities의 업무 구조이며 표시용 아이콘 기능으로 대체하지 않는다.

## 남은 출시 조건

사용자는 Supabase·OpenAI 연결이 아직 없다고 확인했다. [연결 준비 안내](connection-setup.md)를 제공했으며 OpenAI Platform 도구는 재인증이 필요하다. 실제 모델·Supabase·외부 MCP10종·세 호스트 로그인/버전·공식 서명/배포·깨끗한 Windows 환경은 준비와 실제 증거가 필요하다. 비밀키를 채팅/ZIP/로그에 넣지 않는다. 독립 구현·시험을 계속하며 미준비 실제 연동을 가짜 성공으로 바꾸지 않는다.
