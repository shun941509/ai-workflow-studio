# 실제 연결 준비 안내

2026-10-28: 사용자는 Supabase 프로젝트와 OpenAI API 연결이 아직 없다고 확인했다. 현재 코드·로컬 테스트는 계속 진행하며 실제 계정 검증은 준비 대기다. 아래 준비는 외부 계정 생성·유료 사용·배포 완료를 뜻하지 않는다.

## 준비할 것과 저장 위치

|연결|준비할 것|저장 위치|확인할 실제 동작|
|---|---|---|---|
|Supabase|프로젝트 URL, publishable 공개 키, 이메일 인증 가능한 테스트 계정 2개|웹 서비스의 환경 설정. 로컬 검증은 `apps/studio-web/.env.local`|로그인, 프로젝트 저장·재열기, A/B 계정 격리, private Storage, 공개 자료 검색|
|OpenAI|Platform 계정·프로젝트, API 사용 가능 상태, 사용할 정확한 모델 ID, 승인한 API 연결|Runner의 ‘AI 연결’. 키는 Windows DPAPI 저장소에 암호화 보관|입력 토큰 계산, text/JSON 응답, 취소·실패·사용량 기록|
|관리 스캔 작업자|Supabase의 서버 전용 접근 권한, 별도로 관리하는 검수 정책과 신뢰 키|운영 작업자의 비밀정보 저장소|고정 후보 다운로드·스캔 기록·권리 증거 확인|
|공개 ZIP 전달 서버|Supabase 서버 전용 secret, 현재 권리 근거·별도 패키지 서명 신뢰 목록, private 배포 Storage|웹 서버의 비공개 환경 변수 `SUPABASE_SECRET_KEY` (기존 service role 키만 호환)|로그인 확인, 원본 ZIP 해시/서명 검사, 다운로드 직전 철회·만료 재확인|
|개인 복사·보관 자료|동일한 서버 전용 secret, 009·010 migration, private `authoring-imports` 버킷|웹 서버 비밀정보 저장소|별도 복사 권리, 원자적 계정 복사, 고정 자료 연결·재내보내기, 같은 요청 복구|

처음 두 연결부터 준비한다. 관리자 작업자의 비밀키·공식 배포 서명 키는 일반 웹 화면이나 프로젝트 ZIP에 넣지 않는다. 비밀키·비밀번호·토큰은 채팅에 붙여 넣지 않는다.

직접 작성한 텍스트 자료와 자료 없는 개인 프로젝트 저장에는 서버 secret이 필요하지 않다. 공개 자료의 개인 복사와 복사한 원본 파일의 연결·재내보내기는 서버 전용 Storage 확인이 필요하다. 해당 기능을 운영할 때만 서버 비밀정보 저장소에 secret을 설정하며 `NEXT_PUBLIC_` 이름을 붙이지 않는다. 아직 실제 공개 파일·서명키·권리 검수 증거는 준비되지 않았고, 설정만으로 공개 자료가 생기거나 배포가 완료되지 않는다.

## Supabase

1. [Supabase Dashboard](https://supabase.com/dashboard)에서 이 서비스에 사용할 프로젝트를 준비한다. 데이터 저장 지역·운영 요금은 프로젝트 생성 화면에서 확인한다. 비밀번호는 별도로 보관한다.
2. 프로젝트 URL과 **publishable 키**를 확인한다. 새 공개 키를 기본으로 사용하며 기존 legacy anon 키만 호환한다. secret 키나 service_role 키는 RLS를 우회하므로 공개 설정에 넣으면 안 된다. [공식 API 키 안내](https://supabase.com/docs/guides/api/api-keys).
3. `apps/studio-web/.env.example`을 참고해 `apps/studio-web/.env.local`에 다음 공개 설정을 지정한다. `.env.local`은 Git 제외 대상이다. 모델 API 키는 이 파일에 필요하지 않다.

```dotenv
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
STUDIO_PUBLIC_ORIGIN=
```

4. 연결 후 검증된 DB migration을 순서대로 적용하고 private Storage/RLS를 함께 확인한다. 현재 저장소의 SQL 시험 통과는 실제 Supabase 프로젝트에 적용되었다는 뜻이 아니다. 기존 데이터가 있는 프로젝트에는 적용 전 상태를 확인한다.
5. Auth의 Site URL과 허용 redirect URL을 실제 서비스 주소로 맞춘다. 로컬 검증 주소와 운영 주소를 섞지 않고 운영에는 정확한 주소를 등록한다. 이메일 인증을 켠 상태로 회원가입·인증·로그인을 확인한다. [공식 redirect 설정](https://supabase.com/docs/guides/auth/redirect-urls).
6. 서로 다른 테스트 사용자 두 명으로 A의 비공개 프로젝트·자료·파일을 B가 읽지 못하는지 검증한다. 이메일 인증 발송 제한과 운영 SMTP도 출시 전에 확인한다.

공개 키가 없으면 브라우저 초안 기능을 계속 사용한다. 공개 설정에 비밀키를 넣으면 앱은 빌드 전에 중단하며 값을 오류 메시지에 출력하지 않는다. 이 형식 검사는 키의 실제 유효성이나 서버 권한 검증을 대신하지 않는다.

## OpenAI

이 세션의 OpenAI Platform 연결 도구는 재인증이 필요하다고 응답했다. Codex 앱의 연결 관리에서 OpenAI Platform을 다시 인증한 뒤 보안 설정 흐름으로 연결을 준비한다. 현재 새 키 생성·파일 저장·실제 모델 호출은 하지 않았다.

Platform의 프로젝트와 API 사용 가능 상태를 확인하고, 실제 사용할 모델 ID와 사용 한도를 정한다. 준비한 연결은 Runner의 ‘AI 연결’에서 관리한다. 일반 AI 작업은 대화용 연결을, 벡터·혼합 검색은 별도의 문서 검색용 연결을 만든다. 문서 검색용 모델은 `text-embedding-3-small`·256차원으로 고정되어 있다. 연결 이름·모델 ID·API 키를 저장한 다음 가져온 워크플로가 요구하는 연결에 맞춰 선택한다. 저장과 실행 준비 검사만으로 모델을 호출하거나 사용 검증 완료로 표시하지 않는다.

실행 시 입력 토큰 계산과 응답 생성에 필요한 작업 내용·지침·연결한 자료가 공급자에게 전송된다. RAG의 로컬 `o200k_base` 문맥 계산과 공급자가 반환하는 실제 사용량은 별개다. Codex·Claude Code·OpenCode의 구독도 Runner의 모델 API 연결과 별개로 검증한다.

검색 결과 다시 정렬을 쓰는 워크플로는 **검색 재정렬용** 연결을 추가로 요구한다. 이 연결은 `gpt-5.4-mini-2026-03-17` 고정 모델이며 같은 모델 이름의 대화용 연결과 구분한다. 키워드 검색에서도 재정렬을 켜면 검색어와 후보 원문이 토큰 확인·재정렬 요청에 전달된다. 기본 실패 동작은 중단이다. ‘원래 순위 사용’을 선택해도 권한·무결성·예산·취소·결과 불명 오류를 우회하지 않는다. 실제 모델 접근과 품질 확인 전에는 검증 완료로 표시하지 않는다.

Agentic RAG는 `gpt-5.4-mini-2026-03-17`을 사용하는 **대화용 연결**을 요구한다. 현재 실행에서 만든 키워드 색인을 대상으로 제한된 재검색을 수행하며, 질문·원문 근거·이전 검색 단계가 모델에 전달된다. 모델 접근 권한이나 실제 답변 품질은 연결 저장만으로 확인되지 않는다. 현재 추가 질문·벡터/혼합 Agentic 검색은 지원하지 않는다.

## 연결 후 검증 순서

1. 웹 설정을 확인하고 로그인 → 프로젝트 저장 → 재열기 → 계정 격리·파일 권한을 확인한다.
2. Runner에 승인된 모델 연결을 등록하고 최소한의 비민감 입력으로 text/JSON 작업을 각각 한 번 실행한다.
3. 입력 토큰 계산·예산 예약·실제 사용량·실패/취소 기록을 대조한다. 유료 실행은 승인한 범위에서만 한다.
4. 동일한 원본 워크플로로 Codex·Claude Code·OpenCode의 ZIP 가져오기·MCP 연결·실행·재접속을 확인한다.
5. 실제 증거를 해당 작업/호스트/버전/해시에 기록한다. 내부 대역 테스트나 문서만으로 usable/published 상태를 올리지 않는다.
